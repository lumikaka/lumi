# 设定图的用户参考

用户附带图片或提供图片链接并要求参考时使用。本流程覆盖批量设定板、单项设定图及其重绘。没有用户参考图时，按已保存的用户要求和画风核对设定图。正文仍通过 `prepare_page_image` 引用已核对的设定图，不额外附加用户原图。

## 1. 看图并区分用途

在决定画风、复用设定或渲染设定生图提示词之前，实际查看用户原图。记录每张图的附件名称／编号、用途和用户要求；有本地路径时只使用附件或工具提供的真实路径。链接包含多图时核对实际下载内容与看到的图片是否一致，选择能体现目标线条、造型、色彩及文字表现的原图；不能用同篇来源代替视觉核对。

优先级为：**用户明确要求 > 用户指定参考图的视觉特征 > 代理自行选择的细节**。用户明确改变比例、配色或字体时按用户要求，并记录有意偏离的依据；“细节你决定”“直接做完”和读者年龄不授权替换指定画风。新增审美要求必须能追溯到用户要求或看过的原图；不要自行加入大头短肢、毛绒、柔光、低饱和等默认风格。角色物种、服装等身份创新与表现画法分开描述，原创角色也应遵循目标造型语言。

- **画风参考**：提取造型与头身比例、五官画法、轮廓线粗细、色彩与饱和度、笔触与纸感、明暗与空间表现。描述可核对的特征，例如“点状眼睛、扁平色块、弱明暗、可见纸纹”，不要只写“温暖、可爱、手绘”。不要把参考图中的人物、剧情、文字或版式自动带入新故事。
- **对白／旁白字体**：参考图有独特字形时，将笔画粗细、手写不规则性、字形宽窄、字距、基线起伏及气泡形态作为画风一起记录。用新故事的逐字文字和项目语言延续这些特征，不复制参考原文、不臆造字体名称；跨语言延续笔触和节奏，不声称字形能一一对应。用户另指定字体、排版或可读性取舍时以用户要求为准，不能自行用“儿童易读”把字体统一换成粗黑体／圆体。
- **角色／场景／道具参考**：提取身份、结构、服饰和固定配色等需保留的特征。用户另指定画风图时，这些图负责主体身份，画风图负责表现方式；不能让旧角色图的画法覆盖新画风。
- **故事参考**：读取文字、情节和顺序，用于故事与分镜；除非用户同时要求参考其视觉表现，否则不作为设定图的画风来源。

同一张图可以有用户明确指定的多个用途。仅说“参考这些图”时，根据任务和图像内容判断并简短说明；存在无法兼容的要求时再澄清。没有画风参考时，不自行从故事截图中指定新画风。

新项目在 `project_setup update` 中将画风提取结果写入 `overall_style`，将参考用途及用户限制写入 `generation_brief`，再按最新 revision 定稿。提取描述用于约束和复核，**不替代图片输入**。已定稿项目不能重新 update/finalize setup；将本次参考要求保存在相关设定 `summary` 和设定生成任务输入中，不谎称已修改项目全局画风。若本次要求与已保存的全局画风冲突，需先通过可用的画风编辑入口解决，不能带着相互矛盾的规则继续生成。

字体特征须保存在 `overall_style` 并进入页面 `storyboard_md`：正文合图通常只有无字设定，不能指望它自动传递原图的字体。逐字内容与字的画法分别约束。保存设定和分镜前检查是否加入与目标画风冲突的比例、材质、颜色或字体；发现冲突先改文字源头，不只在末尾追加一句“保持参考画风”。

## 2. 组织本次设定图输入

先 `settings list/get`，需要比较已有图片时调用 `read_image`。有图只代表可读取，不代表符合用户指定画风。只复用符合本次要求的项；画风不符的项保留身份特征，携带原图按目标画风重绘，并按同一 setting_uuid 的最新 revision 更新，不删除旧版本或另建同名设定。

为每次调用列出实际需要的视觉参考：用户画风原图，以及本次主体所需的身份／场景／道具参考。画风参考适用于各批；某个角色的身份参考只用于含该角色的批次。故事用途的图不主动作为视觉输入。

批量用 `render_prompt(target=setting_board, prompt_group=premise, prompt_key=setting_image)`；在 `variables.input_text` 写明本批主体、从参考提取的具体要求及图片用途对应关系，例如“参考图 A 控制造型与笔触，参考图 B 仅保留角色的辫子和黄色外套”。实际编号／名称须与本次传图一致。使用返回的 `generation_prompt`；不要用 `variables.style_prompt` 覆盖服务端项目画风。单项设定沿用 `image_target` 和目录中的设定模板，同样带上这些参考要求。

批量模板的纯白留边、网格和无字要求只用于裁切，不授权改变主体的比例、轮廓、配色和材质。无字设定板不画字体样张；字体在首张正文实际核对。

## 3. 设定图来源（Claude Code 不能直接生图）

读取图片、在 prompt 中写文件名、把设定 UUID 放入 `context_setting_uuids`，都不等于设定已有图片。可用来源：

| 来源 | 做法 |
| --- | --- |
| 用户提供的真实本地图片文件 | 先用 Read 看图确认内容与用途，再 `image_target(target_uuid, slot=setting_image)` 取 revision，用 `import_image` 传该绝对路径。不要用截图或缩略图替代原附件，不猜资产路径。 |
| 在 Lumi 中生成 | 给出 `web_url(setting_uuid)` 或 `web_url(view=settings)`，说明本次参考要求，请用户在 Lumi 的设定页面用已配置的服务商生成；用户回到对话后 `settings get` 重读并实际看图。 |
| 用户明确接受仅文字设定 | 按用户要求跳过设定图，正文传 `setting_uuids=[]` 并说明理由。 |

不能静默省略参考、只用文字补偿，或宣称已生成。导入时在 prompt 中如实写明图片来源。

## 4. 核对后再用于正文

生成或导入后实际看图，对照原参考及用户要求逐项核对：造型／五官与比例、线条粗细与颜色、配色／饱和度、笔触／材质／明暗、主体身份。分别写出“目标特征—实际观察—通过或待修正”；用户要求的有意偏离注明依据，不当作缺陷。只写“水彩、可爱、已检查”不能代替具体观察。总览图核对通过后拆分，并检查裁切结果是否完整；不合格的图保留历史，按上节来源重新获取并更新同一设定 UUID。裁切无法修复画风。

正文准备前调用 `image_target(...,slot=page_image,setting_uuids=[...])` 读取 `setting_readiness.style_prompt/style_digest` 和每项 `variant_uuid/expected_revision`。`review_required` 只说明图片齐全，尚未提交核对。为每项提交 `setting_reviews`，字段见 [页面生图](page-images.md)：`reference_basis` 记录参考原图及用户明确覆盖要求；`comparison` 写具体对照观察；通过才写 `verdict=passed`。没有原图时以已保存画风为依据。同一图片版本、设定 revision 和有效画风不变时可复用核对记录。

缺少、未通过或过期的核对会被 `prepare_page_image` 与 `generate_page_image` 拒绝。先修正，再重新核对；不能只改 verdict、版本号或摘要骗过检查，也不能用空选择绕过。导入成功不等于画风通过。服务器验证记录与当前事实的对应关系，视觉判断仍由实际看图的代理负责。

首张正文生成后实际对照原参考，复核画风以及对白／旁白字体，再继续余页；发现漂移先修正设定或分镜并重绘这一页。按已有授权自行核对和纠正，不新增用户确认节点。额度或能力不足时说明尚未通过的项目，不宣称完成验收。
