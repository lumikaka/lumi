# 前端业务状态实时同步

Lumi 的业务状态采用“WebSocket 变更通知 + REST 重读 SQLite 事实状态”，不使用定时 HTTP 轮询。应用统一订阅 `/api/v1/ws` 的 project topic；收到业务事件后，只失效事件关联的活动 TanStack Query。首次 join、重新 join、窗口重新聚焦和重新可见时执行项目级校准。

ChatArea 的 workflow 运行诊断沿用同一模型：展开时通过 REST 首次读取 runs、events 和 LLM logs；折叠时不请求诊断接口。`workflow:*` 只刷新 workflow、runs、events 及关联 thread，`llm_log:changed` 单独刷新 LLM logs。分页继续由用户点击“加载更早记录”或“加载更多”触发。

WebSocket payload 只包含公开 UUIDv7、状态和必要定位字段，不包含内部 `id` 或完整诊断数据。断线期间不启用 HTTP 轮询兜底，连接恢复后通过 REST 校准。前端唯一保留的 `refetchInterval` 是独立的 HTTP HealthCard，不属于业务状态同步。
