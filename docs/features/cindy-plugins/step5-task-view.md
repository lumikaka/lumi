# Step 5 · 绘本任务审阅页

## 目标

让用户在 Cindy 当前任务旁查看整本、单页、候选与设定；对话写入后页面及时反映 SQLite 中的事实，界面失败时仍能凭文本继续创作。

## 前置

完成 [Step 4.5](step4.5-task-view-acceptance.md) 的 UI 门槛。读取其产出的 `task-view-acceptance.md`，按实测通信方式实现，不再猜测跨源访问或 worker 生命周期。

## 范围

1. 复用 `web/mcp-app/` 中可共享的展示组件、数据契约、图片加载和 Query 逻辑；抽取最小共用层，保留 Codex MCP Apps 的入口、桥接和构建结果。新 Cindy 入口独立构建，脚本与样式内联到包内 HTML；运行媒体按需读取，不把整本原图嵌进页面。
2. 提供四种视图：

   | 视图 | 内容 |
   | --- | --- |
   | 整本 | 按阅读顺序展示缩略图、每页正文/画面描述、缺图与分页 |
   | 单页 | 当前图片、完整正文和画面描述、历史图片预览 |
   | 候选 | 稳定编号、候选文本/图像、本地选中反馈及对话提交说明 |
   | 设定 | 角色、场景、道具设定与参考图 |

3. 用 taskView 的 `session` 取已建立绑定；没有绑定时提供明确说明。复核所有 target/asset/variant UUID 的项目归属，缓存按项目根绑定、公开 UUID 和尺寸隔离。
4. main.js/worker 的页面读桥使用单独的只读允许列表。页面不能把消息转换成任意 Agent `call_tool`，也不能持有或复用 `callId`。页面自主读取所需 Node 等能力在 manifest 中如实声明。
5. 所有写入仍由对话中的 Agent 工具完成。候选状态明确区分“正在预览”和服务端当前选择；不展示虚假的“已保存”。默认不增加页面直接提交和插件自主调用模型。
6. 采用 Step 4.5 已验证的预览传输；可见项懒加载、有界并发、有容量上限的缓存、过期请求丢弃。区分缺图、加载、拒绝、超时、解码错误和资源缺失，用户可重试单项。
7. 实时链路固定为 server WS → Node → main.js → taskView → TanStack Query 失效 → 桥接 REST 重读。首次 join、重新 join、窗口聚焦全量校准相关查询；提示不携带正文、原图或内部 ID。
8. 页面关闭/任务切换/插件停用时清理订阅和待处理读取；重新打开重新绑定。乱序通知可以合并为失效，不能把通知 payload 当最终事实。
9. 适配 Cindy 主题变量、窄屏与键盘；显式定义 selected/active 与 hover 组合样式。任务页标题和容器由 Host 绘制，不重复造外框导航。
10. 保留完整文本、候选编号和“在 Lumi 中打开”入口。后者遵守实际电脑与 URL 归属：Mac loopback 不能直接当作手机 URL；无远程可用入口时提供文本与可交付文件。

## 手机扩展边界

本步骤主验收是桌面 taskView。将来增加手机审阅时，应为已有 panel/mainView 声明独立 mobile 页面，保持 mobilePageId、requestId 和 48 KiB 桥接上限；图片走受控媒体通道，不能把桌面预览 base64 原样塞进手机业务消息。手机扩展需另有明确实现范围，不因 CSS 可缩放就宣称移动端完成。

## 交付

- Cindy 审阅入口、最小共用 UI 层、只读桥与实时转发。
- `docs/features/cindy-plugins/task-view.md`：视图使用、真实状态同步、错误与恢复、支持范围。
- `docs/features/cindy-plugins/acceptance/step5-task-view.md`：四视图、明暗主题、切任务、断线恢复、失败兜底和 Codex 回归证据。

## 禁止

不在 taskView 做复杂排版/富文本编辑，不直连项目数据库，不开放任意 loopback，不发定时业务读请求，不把已验证的 Codex UI 行为当作 Cindy 验收，不运行 Cargo/Rust。

## 完成标准

四视图真实宿主通过；同项目其他任务写入后无需刷新可见；A/B 任务快速切换不会串图或正文；首次/重连/聚焦正确校准；无变化时无业务轮询。图片失败只影响单项，文本链可继续到导出；共享组件改动后的 Codex 构建和相关测试通过。
