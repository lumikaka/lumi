# Cindy 开发包人工验收清单

本清单供用户另开 Cindy 任务执行。实现与自动化结论见 [审查交付](implementation-review.md)。每项分别记录通过/失败、工具回执或截图；没有执行的项目保持未验。只使用隔离作品，不用 Lumi 仓库目录作为验收作品目录。

## 先选包并检查实际运行版本

1. 默认使用标准开发包 `build/cindy-dev/lumi-dev/lumi-dev-0.4.0.cindy`，更新既有 **local:lumi-dev**，不覆盖正式实例、不另建同名副本。新包只是交付产物，本次没有替你安装。
2. 在新 Cindy 任务里先让 Agent 读取 Lumi 目录和 Manual，再调 `runtime_status`。标准开发预期 channel/environment 均为 development，build_id 为 `5e688bf3082e45875c43811d3f8ea05fcb5eafaa1cc603c37be56ed932275871`；production_tasks 的 schema 应有 `retry_create`。若仍为旧构建，先更新再验，不把旧卡片当新版本。
3. 同时保存 `server_creation_protocol_version`。当前旧共享后台为 9；**历史矩形改图需至少 11**。仅更新插件不会强停或替换后台。可以先验工作区、点选、制作与导出；准备历史裁图被拒时记实际错误并停止该请求。
4. 如你希望专用后台验收，可另行明确选择 `build/cindy-native-acceptance/lumi-dev/lumi-dev-0.4.0.cindy`；它仍更新同一开发实例，但改连 `/private/tmp/lumi-cindy-native-acceptance-20261118-data`，build_id=`c468010b05f6931a26cdcd9e2220d30712c8b871d8e38416d39b8ab26cc1400d`。这会改变所有该开发插件任务使用的后台配置，须由你决定；本次没有安装它。也可先协调现有后台的使用者，再按正式流程明确升级原后台。

## A. 工作区及点选引用

可复制给新任务：

> 使用 Lumi 开发插件，在本任务的独立目录建立一个验收绘本，作品名包含“人工验收”。创建一章，保存两页有明确不同身份的页面，例如“红色圆形·身份页”和“蓝色方块·身份页”。保存完整正文与分镜后，直接用 review_page 打开其中一页。暂不生图、不导出，也不要代替我修改待验标题或添加引用。

- [ ] 卡片中显示与当前任务绑定的作品，工具回执 `can_write=true`。
- [ ] 人工把某页标题改为“人工保存·独立标记”并点击保存；让 Agent 只读复查 UUID、标题及 revision，正文/分镜未随标题改变。
- [ ] 点“引用到 Agent”，等成功提示；确认没有自动发消息。再在**同一任务**输入“刚才选的是哪一页”。答案应来自当轮注入上下文，包含所选页公开 UUID、最新标题和所属章，不能只凭历史聊天猜测。
- [ ] 对比点选前后页 revision、采用版本均未变；保存/采用只由对应按钮触发。输入框标签样式交由 Cindy 决定，不要求模仿 Codex 标签。
- [ ] 分别尝试章、设定、内容卡 @ 引用和文本候选点选；文本候选点击不保存正文、不采用候选；显式采用后才变化。
- [ ] 地址可复制；前进/后退正常；直接打开单页也能返回章节/章列表；菜单的总览、设定、阅读入口正常；重新连接后仍是当前项目。
- [ ] 重开旧卡片、切换项目、同项目另一任务、另一项目任务：旧卡片不得因页面自报 UUID 进入其他项目；绑定变化时提示重开/重读。跨项目读取失败不应返回内容。
- [ ] Cindy 任务处于只读时可读，保存/采用/制作记录/创建任务拒绝；恢复写权限后由新调用核验，不沿用旧授权。
- [ ] 首次连接、WS 断开重连和窗口重新聚焦后，其他操作产生的更新能重读显示；空闲时没有定时 HTTP 业务轮询。记录卡片开关及读写任务身份，不把 SDK 单测当真机结果。

## B. 多章、独立场与依赖场、中断恢复

可复制的制作输入：

> 新建一个独立的两章短绘本。第一章三页：A 红色圆形在白屋左侧找到钥匙，说“钥匙在这里”；B 蓝色方块在另一间白屋桌边打开盒子，说“盒子打开了”；C 紧接 B，蓝色方块从已打开的盒中取出星星，说“原来是星星”。第二章一页 D，红色圆形和蓝色方块在门外会合，分别拿着钥匙和星星，说“我们准备好了”。分镜尚未提供，请逐页起草，经章节负责人核对后串行保存，旁白对白逐字保留。每章统一维护设定，逐页生成、导入、查看采用图并审阅。先默认串行；我另行明确选择时，第一章只允许无依赖的 A/B 最多两场并行，C 必须等待 B 核验。D 必须等第一章交接核验。把交接、草稿、写入回执和未决请求持久保存到 Lumi 制作记录。第一张图成功导入后先暂停，供我中断任务并验恢复。

- [ ] 保存有序 index.json、章记录、分镜 manifest/page-N 和 storyboard-commit；逐页含 source_spans、utterances、continuity。子任务只产草稿，不能直接写本项目或另派角色。
- [ ] 已有可用分镜时不再创建分镜任务；重做时每章复用一个分镜角色。角色任务重复 create 不产生新任务；发送按最新 Host revision。
- [ ] 首次 schedule 默认只放一场；在用户明确选择 A/B 并行后保存 user_choice，最多两个占位，C 在 B 当前采用版 passed、交接已核实、原写者结束后才放行；第二章在第一章实际完成前阻塞。
- [ ] 整章计划不能遗漏首尾/中间页。只有用户明确限定部分页，才保存带原要求的 page_scope；计划后新增页须补齐所有权，不能提前完成。
- [ ] 生成与导入前保存完整原参数、原签名/提示词、稳定键和未决状态。第一张图导入后中断，重开任务先 project_overview → project_setup get → book_outline，再读页摘要/版本和回执。先审阅已有图，不再次生成/导入；章节仍仅两章。
- [ ] 设定返修标 affected_scenes 后暂停相关场；paused/unknown 继续占位；复核通过后才恢复。每页查看当前采用图并保存当前 variant/revision 的审阅证据，不能拿旧版 passed 交接。
- [ ] 发送/创建未知结果先 request_status，再 resume_request 原键原参数核对；没有结果不能换键。明确拒绝则停止。若你主动恢复任务授权且要求重建，retry_create 只能替换已知 PERMISSION_DENIED 的未创建职责，原拒绝回执保留。
- [ ] 最后核对章数、页数、实际生成请求和导入次数。若执行结果未知，只查回执与事实，不为补验重复付费请求。没有 tasks 时当前任务按同样交接/审阅/恢复顺序串行完成，记录该宿主差异。

## C. 从未采用历史版本局部改图

需要上述协议前提满足。可先保存两张明显不同的测试图作为 v1/v2，当前采用 v2，明确指定从未采用的 v1 修改矩形。

- [ ] 准备前读回页 UUID/revision、v1/v2 variant/asset UUID；确认 v1 非当前、v2 当前。按整页坐标选择矩形，不用缩略图坐标。
- [ ] prepare_page_image 返回 local_edit、原尺寸上下文裁图、完整 generation_prompt、签名 preparation。原生通道用原裁图路径；Core 通道用 kind=local_edit_crop 且 status=ready 的 Lumi 受管原图，不用合图或预览替代。
- [ ] 实际请求的图片、提示词和签名保持原样。提交前保存请求参数/媒体 URL/未决键；未知先查回执，不重复请求。
- [ ] receive_media 带原 preparation/prompt，fit_mode=keep。返回 adopted=false；新候选 v3 出现，当前采用仍为 v2。
- [ ] 比较 v3 与基底 v1 的原图像素，选区外变化数为 0，选区内应有符合要求的变化；不能只凭肉眼断言零像素变化。
- [ ] 明确要求采用 v3 后才 select_image；再次读回当前 variant，应等于 v3，原 v1/v2 仍在历史中。
- [ ] 旧 revision 重放被拒绝；中断恢复先重读当前版、历史和导入回执，未知结果不重导。另核对整页合图、无参考图准备及视觉核对仍可用。

若步骤 2 得到 LUMI_CLI_UPGRADE_REQUIRED，记录协议 9/要求 11，停在准备阶段：没有裁图、付费生成、候选或采用。这是当前后台前提未满足，不能据此把新实现说成已验通过，也不要改用 CLI 绕过或擅停共享服务。

## D. 创作与交付回归

- [ ] 项目初始化只在当前任务目录进行，重复调用不重复建项目；setup update 成功后，用实际返回 revision finalize。预设比例只传 mode，custom 才传宽高。
- [ ] 参考图与设定图实际查看并保存具体 comparison/reference_basis；图片准备与导入版本对应，文字描述不能代替视觉核对。
- [ ] Markdown、ZIP、PDF 在实际 Cindy 任务文件列表出现且能打开；生成成功与用户实际取得文件分开记录。
- [ ] 静态网站落到当前项目 website 目录，入口可读；发布提示词与实际回执一致，章节和阅读站顺序遵循 Lumi 当前顺序；没有授权不要直接发布。

验收结束记录失败的具体步骤、错误码、当前项目事实和可行替代操作；无需重跑已确认成功的请求。
