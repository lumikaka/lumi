# Step 4 · 宿主生图导入与页面挂载

## 目标

把 Cindy Agent 生成或用户交付的图片完整保存到 Lumi Asset Store，挂到对应页面/设定，支持参考图、版本历史与柔性比例处理。

## 前置

完成 [Step 3](step3-authoring-tools.md)，Step 0 已验证至少一条合法媒体交接链。阅读开发依据中的媒体、运行时、Node 限制，以及 [现有图片工具](../codex-plugins/tools.md)。

## 图片链路

1. Agent 调用 `image_target`，获得目标、比例、当前 revision 和参考图信息，再用 `render_prompt` 得到画面要求。
2. 当前 Agent 调用已验证的生图路径。Core media 是通用路径；引擎原生生图作为独立能力记录，不能自动切换供应商或把 API 计费宣传为订阅额度。
3. Agent 通过顶层 `ghost_call.attachments` 把生成结果交给插件显式声明的 `receive_media` 工具。业务参数只包含目标公开 UUID、slot、expected_revision、fit_mode、说明/提示词，不接受 Agent 自报指纹或任意本地源路径。
4. main.js 读取 Host 注入的授权附件，通过 Step 0 已验证的自有媒体端点获取原件；未经授权的媒体失败即停止该次导入。`cindy-media://` 不是磁盘路径，不能拼接 Cindy 缓存目录。
5. 原件经有界分块送入 worker 暂存，完整校验后调用现有 Lumi `import_image`。内部暂存路径仅在可信适配层使用，成功回传 Lumi Asset UUID、版本、尺寸、比例处理结果，不向页面泄露暂存路径。
6. 导入确认落盘后释放本次暂存；失败、取消和异常退出清理未提交字节。响应丢失时先重读目标，不重复生成或盲目导入。

## 大小、归属与完整性

- 不能把整张原图 base64 放入单次 Node params：该契约上限为 256 KiB，stdout 单行上限 1 MiB。分块需给 JSON/base64 留余量，具体阈值在实现与验收文档中固定。
- 暂存以随机内部 transfer 标识绑定插件实例、项目、目标与有效调用；校验序号、总字节数、SHA256、MIME/真实格式和解码后像素上限。限制并发与总磁盘占用，禁止路径穿越和跨任务接管 transfer。
- 复用 Lumi PNG/JPEG/WebP 解码、素材去重、原图保留、页面/设定归属、expected_revision 校验。不能只检查扩展名。
- 原图大小超过当前公开交接能力时明确返回限制，保留已有作品；不改传私有路径或绕过 Host 归属检查。
- 同一回执表示素材已经在 Lumi 落盘；仅在 Cindy 媒体库显示成功不能当作项目已保存。

## 参考图与比例

- 参考图优先使用现有 `read_image` 的受控预览，按 Cindy 工具结果图片契约回给 Agent；需要媒体寄存时声明对应能力，验证归属和回送生图输入的真实效果。
- 保留现有预览约束：最长边 256–1024、JPEG 编码不超过 120 KiB，既有 MCP 结果不超过 256 KiB；Cindy 桥接若有更小限制再收紧，不因宿主支持大图而扩大默认载荷。
- 复用 `keep/crop/pad`，保留生成原图与真实尺寸。提示推荐比例但不承诺精确像素，不为小比例偏差反复生图。
- 页面图片与设定图使用同一业务导入路径；新图生成期间用户修改了目标时，返回版本冲突并保留可恢复素材，不自动覆盖新选择。

## 交付

- `receive_media`、受控媒体传输、参考图输出和现有业务导入适配。
- 更新 Cindy 工具文档和 Manual，说明两种生图路径、导入时机及失败恢复。
- `docs/features/cindy-plugins/media.md`：原件链路、大小限制、额度证据、权限与验收矩阵。

## 禁止

插件沙箱/页面不直接请求图片供应商，不持有生成 API key；不扫 Cindy 数据库或媒体目录，不把原图塞进模型文本，不直接改 Asset Store 索引，不运行 Cargo/Rust。

## 完成标准

固定素材覆盖正常/不同比例/损坏/超限/取消/重复块/跨项目/版本冲突；真实 Cindy 至少一张生成图完成授权附件 → 原件校验 → 导入 → 读回预览 → PDF 导出。另测 Lumi 参考图参与一次编辑或重绘。每项区分 fixture、真实宿主、真实模型；未验证的引擎原生生图路径不得写成已支持订阅生图。
