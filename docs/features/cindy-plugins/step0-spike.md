# Step 0 · Cindy 关键行为调研

## 目标

用真实执行电脑上的 Cindy 验证插件运行、项目绑定、媒体和 UI 依赖，确定后续步骤可落地的路径。本步只产出最小探针、可复现材料与结论，不实现 Lumi 产品功能。

## 背景与前置

先读 [总体方案](plan.md)、[开发依据](references.md)，再按当前宿主 `cindy-plugin-creator` Skill 核对版本和源码。已有 `0.1.121` 基线只是文档/源码证据，不复用 Codex App 的运行结果充当 Cindy 验收。

## 需要验证的问题

| 项目 | 最小验证 | 必须记录的边界 |
| --- | --- | --- |
| 宿主身份 | 执行电脑、Cindy 版本、build/sourceCommit 或 tag、系统与 CPU | 手机是控制端时不能用手机版本替代 |
| Node 与 CLI | Forge 打包一个 worker 和现有 Go CLI；读取版本、启动临时数据目录、调用 status | 执行位、签名/Gatekeeper、包体、GUI PATH、主机提供的 Node 运行时 |
| 会话上下文 | 两个本地任务、两个目录分别调用，另测只读/非本地上下文 | `session_id/workdir/workdir_is_local/workdir_is_read_only` 实际值；不保存真实用户路径 |
| 共享 worker | 并发两项目、同项目双任务、worker 崩溃后重试、插件停用/升级 | 原生子进程回收、共享 server 不被误停、路径和结果不串项目 |
| 工具与 Manual | `ghost_info`、分类目录、Manual、错误 schema 与业务失败 | schemaVersion、16 顶层工具上限、能力与批准；不改用户引擎配置 |
| 图片输入输出 | 真实生成后用 `ghost_call.attachments` 过户；逻辑页读取自有媒体并限量传给 Node；参考图回送 Agent | 原件字节/SHA256、实际格式尺寸、体积、过期、越权拒绝；不猜媒体磁盘路径 |
| 生图账户路径 | Cindy Core media 与引擎原生生图分别测一条最小链路 | 实际模型/provider/可观察的额度来源；不能确认的填未知，不凭模型名猜收费 |
| taskView | 包内页、两任务切换、BroadcastChannel、wake、图片、主题与聚焦 | 不假设支持 MCP Apps iframe；不开放 loopback/CSP 作为捷径 |
| 实时桥接 | Node 连临时 Lumi `/api/v1/ws`，转发提示，页面请求重读 | worker 空闲回收、通知是否续命、断线/重连、无变化时是否发业务读取 |
| 消息归档 | 临时任务主动开启 hooks；观察用户/助手、插话、中断、失败、其他 hook 改写；查询任务读取能力范围 | 事件身份与提交时序、重放/缺口能力、普通任务和插件自建任务区别 |
| 手机控制电脑 | 有可用测试条件时，从手机对电脑任务发一次读取/导出请求 | 实际执行电脑、目录、结果交付位置；不把桌面 taskView 当作手机 UI |
| 安装更新 | 开发包安装、同来源更新、停用与卸载 | 宿主确认步骤、实例/namespace、数据保留、真实来源和版本回执 |

## 交付

- 探针放在 `docs/features/cindy-plugins/spike/`，数据使用独立临时项目与 data-dir，保留操作清单和清理范围。
- 产出 `docs/features/cindy-plugins/spike.md`：每项包括结论、证据等级、可复现步骤、版本、实际回执、限制与下一步。
- 源码/文档、自动化、真实宿主、真实模型分别标注。没有账号/工具/授权/测试设备时写明待验证，继续完成独立项目。
- 打包只用 Forge 的公开流程。安装或真实生成按当前明确授权和宿主权限执行；尚未授权安装时先交付可审阅探针包，不修改已安装目录或批准配置。

## 后续步骤的门槛

1. Step 1：随包 Node 能执行选定 CLI、任务上下文可用、项目隔离方案明确。
2. Step 4：至少一条合法的媒体原件交接链路成立；未成立时列为阻塞，不能退回扫描 Cindy 私有缓存。
3. Step 4.5/5：任务页能通信与取图；连续通知生命周期不能保证时，先明确需要的声明或宿主缺口。
4. Step 6：实际打包与最低正式宿主版本有依据，安装体验如实记录。
5. Step 7：默认不采集；消息身份和范围不足时只设计有限归档/手动导入，不承诺完整历史。

## 禁止

不改 `cmd/`、`internal/`、`web/` 产品代码，不改旧插件；不触碰真实作品，不关闭权限或 CSP，不下载执行代码来绕过随包限制，不在本地运行 Cargo/Rust。

## 完成标准

表内每项都有“通过/失败/未验证”的明确结论，附证据；文末逐项给出对 Step 1–7 的影响。所有非临时改动、残留进程、测试安装实例均有记录。仅门槛已通过的步骤可以进入对应实现。
