# Step 7（可选）· Cindy 创作记录归档

## 目标

在用户主动启用时，把明确范围内的 Cindy 创作文本保存为 Lumi 项目中的只读记录，便于桌面回看。默认关闭，不影响 Step 1–6 的作品创作与导出。

## 前置与能力门槛

完成 [Step 6](step6-plugin-install.md)，先复核 Step 0 的消息证据，并阅读开发依据中的事件、消息钩子与任务接口。

- `did-turn/session/activity` 主要是元数据，不是消息正文或完整工具轨迹。
- `will-user-message` 发生在发送前；后续 hook 可能改写/阻止。收到这条事件不能直接标记为最终已发送消息。
- `will-assistant-message` 是回复后处理点，不能据此保证所有 commentary、工具结果、图片和历史消息均被交付。
- `cindy.tasks.readMessages` 受本插件创建的本机任务归属限制；不能用它归档任意已有用户任务。不得为了读取历史而静默把用户当前任务换成插件自建任务。
- hooks 要求 resident，并扩大消息访问权限；开关的产品意愿与 Host manifest 能力批准是两层，均须真实满足。

## 先完成的小范围验证

用临时任务测试普通发送、插话、同内容重复发送、重试、失败、中断、重启、其他 hook 改写/阻断；确认稳定消息/事件键、真实提交状态、排序、丢失提示及可补读范围。仅按文本 hash 去重会误删用户真实重复消息，不采用。

按证据选择并明确标注交付范围：

1. 有稳定标识与提交事实时，提供被支持范围的增量归档。
2. 只有实时钩子文本时，只能称为“启用后捕获的创作记录”，标明来源阶段、覆盖范围和缺口；不称为完整聊天历史，不把发送前文本冒充最终消息。
3. 连有限归档都无法可靠绑定/去重时，缩减为用户主动提供的宿主公开导出文件手动导入；若宿主没有可用公开导出，也明确记录能力缺口，不扫描 Cindy 私有数据库或 Codex rollout。

## 范围

1. 用户显式为某个 Lumi 项目/任务启用，说明保存内容、开始时间和停止方式。只处理已建立并复核的任务绑定；其他任务文本不持久化、不写日志。
2. 使用独立受限归档入口，通过 CLI/server 与项目锁写入。拟新增接口按 REST 资源设计，明确来源、公开项目/记录 UUID 与幂等键；不伪造 Codex 的现有导入格式。
3. 只保存用户/助手文本和能被公开接口证明的 Lumi 工具摘要；不收 reasoning、系统/开发者提示、原始参数/输出、图片字节、凭证或任意命令日志。工具摘要不足时省略，不推断成功。
4. 新建独立 `cindy_session` 或经过明确兼容设计的宿主中立只读类型；保持 `codex_session` 旧数据与导入行为。内部关系使用 bigint 自增 ID，API 使用独立 UUIDv7，Host 不透明标识只作为来源字段。
5. 不写入/伪造 Lumi 原生 `chat_runs`、`chat_turns` 运行状态。migration 向后兼容、可验证旧数据保留；必要时拒绝有损降级。
6. 自动采集不能阻塞聊天：入口钩子在宿主期限内 allow；后台持久化用有界队列和幂等键，失败/溢出/断线明确记录缺口。没有可靠补读来源时不承诺补齐。
7. 禁用立即停止后续采集，不删除已有记录；卸载不删除用户项目。归档失败不影响创作工具、任务页或图片导入。
8. 桌面 ChatArea 标记“Cindy · 只读”及实际覆盖范围，无输入框/虚假运行轨迹。归档提交后经 WS UUID 提示失效 Query，REST 重读；不轮询宿主历史。

## 交付

- 与实测范围相符的归档/手动导入能力，默认关闭的开关，以及必要的独立权限版本。
- `docs/features/cindy-plugins/session-archive.md`：选择的路径、权限、记录范围、去重依据、缺口与恢复、真实验收。
- 脱敏 fixture、迁移和只读 UI 测试；不把用户真实聊天全文提交到仓库。

## 禁止

不默认采集，不宣称 hooks 提供完整 transcript，不读 Cindy 私有数据库，不改用户消息正文，不后台扫描所有任务，不用本次归档授权扩大到任意历史读取，不运行 Cargo/Rust。

## 完成标准

首次/增量/重复投递、同文本不同消息、乱序、中断、关闭开关、跨任务拒绝、格式未知和队列缺口均可解释；桌面只读展示正确，旧 Codex 导入兼容；无正文泄露到日志，用户聊天不被归档失败阻塞。证据不足时交付明确降级与未实现项，不把“可选”当作已完成。
