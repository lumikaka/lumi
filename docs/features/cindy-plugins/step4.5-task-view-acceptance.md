# Step 4.5 · taskView 宿主行为验收

## 目标

在真实 Cindy 中验证任务页、图片、请求路由和实时提示，确定 Step 5 的生产通信方式。本步只补最小探针和必要诊断，不提前实现整套审阅界面。

## 前置

完成 [Step 4](step4-image-import.md)。准备两个不同的临时 Lumi 项目，各含一张真实导入图片；使用当前执行宿主的 taskView/面板/Node 文档。普通浏览器、模拟 bridge 和 Codex MCP Apps 的通过记录都不能替代本步。

## 验收清单

1. **真实开页**：声明包内 `taskView.html`，由逻辑页调用 `cindy.taskView`，使用回执确认实际 session；后台调用不抢用户焦点。验证切任务、重开页、最大化及明暗主题。
2. **绑定与隔离**：页面 `session` 与工具建立的绑定匹配；篡改 project/session、未知绑定、worker 重启后的旧页面不得访问另一个项目。两页并发请求不会混用响应。
3. **页面通信**：`/wake`、BroadcastChannel 与 requestId；晚到响应、乱序、重复请求、页面关闭后清理。有界唤醒握手重试只用于传输就绪，不能变成业务轮询。
4. **图片**：验证本插件有权使用的媒体 URL 或受控预览字节链路；沿用真实产品预览上限。记录图片 hash、尺寸和目标 Asset UUID，验证缺图、解码失败、切页过期响应与缓存隔离。
5. **读取与选择**：页面只读工具能够重读内容；候选选中只影响本地状态；用户在对话给出编号后，Agent 经已有工具提交并触发 UI 更新。不在本步借页面测试直接业务写入。
6. **实时状态**：Node 连接 `/api/v1/ws`，按既有 `topic/event/payload/ref/join_ref` 转发变更提示，页面失效 Query 后经 REST 重读。检查首次 join、断线/重新 join、窗口失焦/聚焦、worker 回收/恢复。
7. **持续连接生命周期**：保持界面打开超过 worker 默认空闲窗口，确认 WS 能否持续；需要 resident/长请求时记录真实声明和代价。不能把通知是否续命当作推测。
8. **失败与安静窗口**：Host 拒绝、Node 崩溃、CLI 关闭、页面重载时状态如实显示；没有业务变化时不重复请求 REST 或 MCP 读工具。WS heartbeat 可保活，但不得触发业务查询。
9. **手机边界**：有条件时记录手机控制 Mac 的文本/图片结果；手机无法看到 taskView 不计为桌面失败，但明确不能宣称手机审阅通过。若另加 mobile 页面，按独立来源与消息大小契约验收。

## 交付

- `docs/features/cindy-plugins/task-view-acceptance.md`：版本、manifest、真实 UI 截图/观察、调用回执、图片证据、实时日志及未验证项。
- 探针放在 `docs/features/cindy-plugins/spike/`，只访问临时项目；安装和移除测试实例按本步明确授权及宿主确认执行。
- 文末给出 Step 5 的固定方案：页面读桥、取图路径、WS 转发方式、worker 生命周期、读写边界和文本兜底。

## 禁止

不关闭 CSP/导航守门，不让页面直接连 loopback/SQLite，不以定时轮询补通知缺口，不用合成巨型 padding 替代真实图片，不改已有作品或宿主安装文件，不运行 Cargo/Rust。

## 完成标准

开页、任务隔离、受控取图、真实 WS 驱动重读及首次/重连/聚焦校准均有证据后进入 Step 5。某项不成立时保留工具文本路径，明确 UI 阻塞和所需调整；不得把文本兜底标为 taskView 已完成。
