# MCP Apps 链接打开修复与验证

日期：2026-11-03（Asia/Shanghai）。实现提交为 `4e797de`。自动化、开发构建及同一链接组件在真实 Codex MCP Apps 中的请求/反馈/复制兜底验证已完成。已取得原始 JSON-RPC 响应：宿主正常返回空结果，用户确认没有可见跳转。**这不是新版完整工作区在新聊天中的全面验收，也不能证明宿主内部为何没有跳转。**

## 确认的原因与证据

- 旧 `OpenLumi` 先阻止普通链接默认行为，再请求宿主。它没有等待状态，只在 `isError` 或 rejection 时显示同一句备用提示；正常 resolve 完全没有反馈。`DownloadLink` 有相同缺口。即使宿主确认接收请求，用户也无法判断点击是否生效。
- 后续在真实 Codex 沙箱运行提交 `4e797de` 的相同 `AppBridge`、`HostLink` 与链接逻辑。用户亲手点击后，旧版等价请求收到 `{"result":{},"jsonrpc":"2.0","id":4}`；新版组件请求收到 `{"result":{},"jsonrpc":"2.0","id":6}`。用户确认“没有可见跳转”。本次可明确分类为“宿主正常返回，但没有可见跳转”，不是未发出请求、显式 `isError`/JSON-RPC 错误或超时；宿主也未报告方法或参数错误。新版正确显示“已请求打开，无法确认外部页面是否已显示”。[原始请求/响应与验证记录](open-link-20261103.json)保存了本次数据。
- 旧 `AppBridge.request` 在 `postMessage` 同步抛错时没有移除 pending/timer；超时取消通知本身再抛错还可能阻止请求结束。测试覆盖并修复了这些桥接处理问题。
- 在真实 Codex MCP Apps 侧栏打开已连接的隔离作品“星光旅途 · 四层审阅测试”，状态“已同步”；点击旧“在 Lumi 中打开 ↗”后 DOM 无提示变化，未观察到新 Chrome/IAB 页。地址来自真实 `review_book` 返回值：`http://127.0.0.1:57738/projects/01a19f54-83ce-75df-93aa-3274fb4ea18c/`。随后在 Chrome 直接访问该地址，正常显示作品主页。
- Codex 当天日志 `codex-desktop-d1ff08a0-227c-42f2-8f2c-70a8035adfc4-39547-t0-i1-091220-0.log:19962–19963`：`2026-11-03T14:32:35.377Z` 收到 `method=openExternal`，相同 operation 在下一行以 `durationMs=0.20000004768371582` 完成。它支持“本次点击到达宿主打开处理器”，**不是原始 `ui/open-link` 响应，也不能证明浏览器已打开或宿主已允许链接**。

不能确认的宿主行为：最终 URL 安全策略判定、宿主有无调用系统浏览器，以及返回空结果却无可见跳转的内部原因。未把 localhost 限制当作结论，也未修改宿主权限或 URL 策略。

## 官方契约

查阅 OpenAI [Reference](https://developers.openai.com/plugins/reference) 后，按其指向核对 MCP Apps 官方 [OpenLinkRequest](https://apps.extensions.modelcontextprotocol.io/api/interfaces/app.McpUiOpenLinkRequest.html)、[OpenLinkResult](https://apps.extensions.modelcontextprotocol.io/api/interfaces/app.McpUiOpenLinkResult.html)、[HostCapabilities](https://apps.extensions.modelcontextprotocol.io/api/interfaces/app.McpUiHostCapabilities.html) 和 [规范](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/draft/apps.mdx)。

- 方法 `ui/open-link`，参数 `{ url: string }`。
- `hostCapabilities.openLinks` 声明打开链接能力；新版保存初始化结果并检查该能力。
- 空对象 `{}` 是规范允许的结果；可选 `isError: true` 表示宿主报告打开失败。JSON-RPC `error` 是另一条失败路径。
- 未新增或依赖臆测的 `success`、`opened` 等字段。Promise resolve 只显示“已请求打开，无法确认外部页面是否已显示”。
