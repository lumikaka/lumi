# Step 4 · 宿主生图导入与挂载

## 目标

让 Codex 用自带能力生成的图片，通过 Lumi 工具导入项目并挂到正确位置（页面画面、角色或场景设定等），比例不符时给出引导而不阻塞用户。

## 背景

- 方案：`docs/features/codex-plugins/plan.md`。比例约束：「可以引导建议，不要那么严格，用户不阻塞优先」。
- 调研结论：`docs/features/codex-plugins/spike.md`，尤其是生图产物的落盘位置和 MCP 进程能否读取。
- Step 3 已提供 stdio MCP 与页面 / 设定工具。
- 现有尺寸规则：`internal/picturebook/sizing.go`（`ResolveImageSize`、`exactRatio`）对服务商输出要求精确比例；宿主生图不适用这种强校验。
- 资产写入必须经过 Asset Store（`internal/files`、`docs/asset-storage.md`），不得直接写 `assets/`。

## 范围

1. `import_image` 工具：参数为本地文件路径、目标对象 UUID、目标槽位（如页面画面、设定图）及可选说明 / 生图提示词。
   - 按路径读取，不接受 base64 大字段。路径由模型从宿主生图结果中取得后传入（调研中 App 返回的是提示文本里的路径，不是 `savedPath` 字段）；不得硬编码 `~/.codex/generated_images`、文件命名规则或 `savedPath`，也不扫描目录猜测。生成图的保留期限未知，skill 要求生图后立即导入。
   - 支持 PNG、JPEG、WebP；校验文件大小上限、真实格式（不只看扩展名）、可解码性。
   - 通过 Asset Store 提交，生成新的图片版本并挂到目标位置，保留历史版本。
   - 记录来源（如 `host_generated`）与原始提示词，便于桌面版区分。
2. 比例处理（调研实测：请求 `384×256` 实际得到 `1536×1024`，方形为 `1254×1254`；宿主只能引导宽高比，不能控制像素，偏差是常态而非例外）：
   - 与项目 / 页面目标比例一致（允许小误差）时直接使用。
   - 不一致时默认仍然导入，在返回结果中给出偏差和建议（例如下次生图应使用的尺寸描述）；按参数可选择原样、居中裁切或补边。
   - 导出 PDF 时，对比例不符的图片有确定且合理的版式处理，不报错中断。
3. 提供一个查询工具，返回当前页面或设定的目标比例、推荐的生图宽高比（宿主常见输出中最接近的一档，如横版 3:2、方形 1:1）与推荐生图描述，以及导入时建议的默认处理（裁切或补边），供 skill 在生图前调用。
4. `read_image` 类工具：把项目内图片以 MCP 图片内容返回（控制尺寸），供 Codex 审阅或作为参考。调研证实 MCP 返回的图片进入对话后可作为宿主生图的参考（`num_last_images_to_include`），用于角色 / 场景一致性：先 `read_image` 设定图，再生图。

## 禁止

- 不调用任何图片服务商。
- 不修改旧 MCP 逻辑（`internal/mcpserver`、`codex-plugins/`）。
- 不改变服务商生图路径对精确比例的现有校验。
- 不运行任何 Cargo / Rust 命令。

## 完成标准

- 测试覆盖：比例正确、比例偏差（原样 / 裁切 / 补边三种）、伪装扩展名、超大文件、不可解码文件、路径不存在、目标 UUID 不存在、版本冲突。
- 扩展 Step 3 的端到端测试：导入多张不同比例的测试图片到页面 → 导出 PDF 成功。
- web UI（CLI 实例，或 CLI 释放项目锁后的桌面版）能看到导入的图片版本与来源标记。
- 更新 `docs/features/codex-plugins/tools.md`。
