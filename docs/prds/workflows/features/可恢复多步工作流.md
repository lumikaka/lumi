# 工作流 — 可恢复多步工作流

## overview

该 Feature 将需要多个业务步骤的操作表示为可恢复 Workflow。它保存输入快照、幂等键、冻结模型、当前步骤、步骤输入输出和 append-only 事件；步骤可以等待用户输入、关联通用任务或创建领域资源，而业务域仍对实际写入负责。异步 Generation 还接受进程内可信 Invocation Context：`direct_ui` 创建独立 Thread，`chat_tool` 复用当前 Thread 并等待完成，`workflow_step` 不增加展示 Thread。

Workflow 的创建入口和 Worker 都要求项目 `setup_status=ready`。`draft` 项目以稳定 `project_setup_incomplete` 失败，不能通过 Agent in-process dispatcher、直接 HTTP 或在定稿前已排队的 Job 绕过；该门禁不影响当前普通 Chat 和 Project Setup 定稿流程。

对话式项目创建是 dedicated Workflow 的受控入口：bootstrap Agent 仅提交 YOLO Brief，服务端从可信创建会话生成幂等键并创建独立 Thread。它不采用普通 `chat_tool` 的 inline await；创建响应持久化后原 Turn 立即完成，Workflow 按既有 Job、Step 和恢复机制独立推进。重复 Tool 恢复只读取同一个 Workflow，不新增 await、Thread 或首步 Job。

## data_model

Workflow 状态为 `queued`、`running`、`completed`、`failed`、`cancelled` 或 `interrupted`。Step 状态额外允许 `pending`、`waiting`；每个 Step 保存公开任务/资源 UUID 以支持前端定位，内部外键不进入外部响应。

Chat Tool 调用额外创建唯一 `workflow_awaits` 记录，状态为 `waiting|ready|resuming|resumed|cancelled`。受现有表约束，`chat_turns` / `chat_runs` 在等待期间保持 `in_progress`，REST Turn DTO 投影为语义等价的 `waiting_for_workflow`；是否可恢复、归属 Tool Execution 与 Resume 投递均以 await 为事实，不以进程内 goroutine 为事实。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/projects/:project_uuid/workflows` | GET / POST | 查询 Workflow 或创建 YOLO Workflow。 |
| `/api/v1/projects/:project_uuid/workflows/:workflow_uuid` | GET | 读取 Workflow 投影和步骤状态。 |
| `/api/v1/projects/:project_uuid/workflows/:workflow_uuid/runs` | GET | cursor 读取运行诊断。 |
| `/api/v1/projects/:project_uuid/workflows/:workflow_uuid/events` | GET | cursor 读取 append-only 事件。 |
| `/api/v1/projects/:project_uuid/workflows/:workflow_uuid/llm-logs` | GET | 按 Workflow 或公开 Step UUID 筛选调用日志。 |
| `/api/v1/projects/:project_uuid/workflows/:workflow_uuid/cancellations` | POST | 请求取消。 |
| `/api/v1/projects/:project_uuid/workflows/:workflow_uuid/retries` | POST | 基于冻结快照重试。 |

Workflow DTO 以 `presentation_mode` 区分 `dedicated_thread|inline|none`；inline 模式返回 `origin_turn_uuid`、`origin_run_uuid`、`origin_tool_call_uuid`、`origin_item_uuid` 和 `await_status`。Invocation Context 不属于公开请求体，HTTP 客户端不能伪造调用来源或父 Run 归属。

## others

Workflow payload 递归净化内部 ID、路径和密钥。终态恢复只读取持久化的脱敏 Workflow/Step 结果：成功 Tool Result 返回公开 Workflow、Task、Resource UUID 和结果摘要；失败或取消返回安全错误码，不泄露 Provider 原始错误。

Workflow 终态与 `ready` await、父 Turn/Run 排队和唯一 Resume Job 在同一 SQLite/River 事务提交。`ReconcileOnOpen` 修复终态但仍 `waiting` 的 await、可恢复但未投递的 Resume，以及已投递 Resume 的幂等重放；活动 `waiting` await 不会作为普通 `in_progress` Run 盲目重跑。重复终态、取消、Resume 或应用重启不得产生第二个 Workflow、await、Tool Result 或有效 Resume Job。
