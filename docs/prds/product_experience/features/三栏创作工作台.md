# 产品体验 - 三栏创作工作台

## overview

### 目标

Lumi 的主任务不是分别浏览项目、聊天和素材，而是在一个项目中持续地“提出创作意图 -> 观察 AI 执行 -> 检查或继续编辑内容”。本 Feature 用稳定的三栏框架承接这条路径：左栏管理跨项目导航，中栏管理当前项目对话，右栏管理当前项目的设定、章节与作品。

界面视觉以 Figma 节点 `1477:9065`、`1477:9176`、`1477:9217` 为基线：白色内容面、暖灰侧栏、14px 主字号、轻边框、低对比辅助信息和仅用于真实资产的卡片。Figma 未提供图标的新入口必须使用文本，不自行绘制图标。

### 用户与主路径

| 场景 | 主路径 | 成功结果 |
|---|---|---|
| 首次使用且无项目 | 新对话 -> 创建项目 -> 填写创作意图 -> 进入项目工作台 | 用户理解 Lumi 以项目承载绘本内容，并能直接发起第一轮创作。 |
| 已有项目的日常续作 | 左栏项目/对话 -> 中栏继续对话 -> 右栏检查设定、章节或作品 | 不离开当前工作台即可完成意图表达和结果确认。 |
| 直接检查项目内容 | 左栏进入项目 -> 右栏切换设定/章节/作品 | 不打开对话也能定位、查看并进入现有领域详情。 |
| 处理进行中或未读会话 | 左栏识别状态 -> 进入会话 -> 查看进度或新回复 | 会话进入后更新已读状态，进行中状态随任务结束消失。 |

### 信息架构与职责

| 区域 | 固定职责 | 不承载 |
|---|---|---|
| 左侧栏，展开宽 260px | Logo、收起、全局新对话、作品库、弱化搜索、按项目聚合的对话、账号入口 | 项目正文、生成详情、重复的顶部导航 |
| 对话栏，桌面宽 400px 左右 | 当前会话标题、消息历史、运行反馈、附件、输入与发送 | 项目资产总览、全局项目切换、独立页面营销内容 |
| 项目画布，占据剩余宽度 | 当前项目内容、全屏/收起、分类筛选、设定/章节/作品切换 | 另一套对话列表、与左栏重复的项目树 |

### 交互原则

1. 项目上下文连续。点击左栏对话后，中栏打开该会话，右栏保留当前项目的现有模式；首次进入项目默认展示“设定”。
2. 对话和画布可独立滚动。输入框和画布模式切换固定在各自区域底部，顶部标题固定在各自区域顶部。
3. 桌面端允许收起左栏和对话栏；收起后必须提供原位恢复入口。画布全屏只隐藏对话栏，不丢失对话状态。
4. 右栏模式使用 URL 表达。设定对应 `premise`，章节对应 `chapters`，作品对应 `comic` 或项目导出视图；切换时保留 `chat_thread_uuid`、`workflow_uuid` 等对话查询参数。
5. 项目概览和低频管理继续通过项目行“进入项目/更多”访问，不占用画布底部三个高频模式。
6. 左栏搜索在主入口中使用弱化图标和文本；点击整行后展开输入。搜索按对话标题过滤，不改变项目数据，也不自动进入结果。

## data_model

本 Feature 不新增数据库表或字段。界面只组合现有公开资源：

- Project：`uuid`、`name`、`open/available/status`、`last_opened_at`。
- Chat Thread：`uuid`、`project_uuid`、`title`、`scope`、`status`、`updated_at`。
- Premise Asset：`uuid`、`asset_type`、`title`、`current_variant`、`tags`、`deleted_at`。
- Chapter：`uuid`、`chapter_code`、`title`、`status`、漫画当前状态。
- Comic Section / Image Variant / Export：沿用故事生产领域投影。

侧栏置顶、已读时间和栏位收起状态继续作为当前浏览器的本地偏好保存，不伪装成跨设备服务端状态。

## api

| 接口 | 方法 | 界面用途 |
|---|---|---|
| `/api/v1/recent-projects` | GET | 左栏项目分组与无项目状态。 |
| `/api/v1/projects/:project_uuid/chat-threads` | GET | 左栏项目对话与中栏对话列表。 |
| `/api/v1/projects/:project_uuid/chat-threads/:thread_uuid/...` | GET/POST | 消息历史、Turn、Workflow、用户输入和发送。 |
| `/api/v1/providers` | GET | 底部 API Key 未绑定或待验证提示。 |
| `/api/v1/projects/:project_uuid/premise-assets` | GET | 设定画布资产卡与角色/场景/道具筛选。 |
| `/api/v1/projects/:project_uuid/chapters` | GET | 章节画布列表与状态。 |
| `/api/v1/projects/:project_uuid/chapters/:chapter_uuid/comic-sections` | GET | 作品画布的已定稿/当前图片。 |
| `/api/v1/projects/:project_uuid/comic-exports` | GET | 项目产物与导出记录入口。 |

所有响应继续遵守统一 JSON 信封。外部路径和 JSON 只使用 UUIDv7；本 Feature 不要求后端返回内部 `id`，也不增加兼容专用接口。

## ui

### 左侧栏

| 元素 / 状态 | 规格 |
|---|---|
| 默认 | 固定展示且默认展开；背景 `#f7f7f5`，宽 260px，左右 8px 内容边距，无底部分隔线。 |
| 品牌区 | 使用 Figma Logo 资产；右侧使用 Figma 收起图标，图标按钮 32x32px。 |
| 主入口 | 顺序为新对话、作品库、搜索；行高 36px，正文 14px。搜索视觉弱化但仍有可访问名称。 |
| 项目标题 | 11-12px 辅助色；hover/focus 显示创建项目入口。 |
| 项目行 | Figma 文件夹图标、项目名和创建对话入口；hover/focus 显示进入项目和更多操作。点击项目名折叠/展开对话，不隐式切换项目。 |
| 对话行 | 与项目文本左对齐；AI 生成标题；右侧只显示未读蓝点或进行中加载圈，已读不显示点。hover/focus 用置顶和归档动作替换状态位。 |
| 展开规则 | 只有一个项目时默认展开全部对话；项目多于一个时每组默认展示最新 5 条，可展开。项目收起后再次展开恢复为 5 条。 |
| 底部 | 仅保留 API Key 提示和本地账号入口。已配置 Key 时隐藏提示；本地账号显示头像和“本地账户”，设置项通过弹层进入。 |
| 收起态 | 保留品牌/展开、新对话和账号等必要图形入口；项目树隐藏，所有图标入口有 tooltip/aria-label。 |
| 数据状态 | 加载显示不改变行高的骨架/短文案；无项目显示简短空态；请求失败显示可重试文本入口；长名称单行省略。 |

### 对话栏

| 元素 / 状态 | 规格 |
|---|---|
| 框架 | 白底，右侧 `#e6e6e6` 1px 边框；顶部 60px；内容左右 24px；桌面宽度约 400px。 |
| 标题 | 当前会话标题，14px；新会话使用“新对话”。线程列表状态提供返回入口但不增加大标题层级。 |
| 用户消息 | 右对齐，最大宽约 294px，浅灰气泡，14px/20px。 |
| AI 消息 | 左对齐、无卡片底色，保留安全 Markdown、附件、用户输入请求、生成进度和错误；赞/踩为次要动作。 |
| 输入框 | 底部固定，外边距 20px，白底、`#e6e6e6` 边框、16px 圆角；placeholder 随场景表达下一步创作。附件在左下，发送在右下。 |
| 发送状态 | 空内容/附件上传中禁用；有内容可发送；运行中保留终止和 steer/follow-up 能力；错误不清空草稿。 |
| 新对话 | 已有项目时直接在当前项目创建；无项目时进入创建项目闭环，创建成功后继续回新对话。 |
| 空/加载/错误 | 首次空会话不显示诊断噪声；历史加载不跳动输入区；错误就近显示并可关闭/重试。 |

#### 输入框状态矩阵

输入框必须由同一个正式组件承载以下状态。验收页不得复制一套静态外观；状态切换只能通过正式组件公开的业务属性驱动。

| ID | 状态 | 触发条件 | 输入与主操作 | 验收预言 |
|---|---|---|---|---|
| `idle` | 空闲 | 无草稿、无运行任务 | 可输入；发送禁用 | 显示场景 placeholder；附件入口按场景出现；发送按钮保持 28px 固定尺寸。 |
| `focused` | 聚焦 | 输入框获得键盘焦点 | 可输入；发送仍禁用 | 外框仅使用轻量 focus 反馈，不改变组件尺寸。 |
| `draft` | 已输入 | 草稿存在且无运行任务 | 可编辑；发送可用 | 发送按钮有明确可用反馈；Enter 发送，Shift+Enter 换行。 |
| `multiline` | 多行输入 | 草稿包含换行或自然换行 | 可编辑；发送可用 | 输入区在约定上限内增高或滚动，不挤压底部附件与发送操作。 |
| `attachment_uploading` | 附件上传中 | 存在 `uploading` 附件 | 草稿可编辑；发送禁用 | 附件展示文件名和“上传中”，上传完成前不可提交。 |
| `attachment_ready` | 附件就绪 | 附件均为 `ready` | 草稿可编辑；发送可用 | 附件可移除；提交时使用对应公开 upload UUID。 |
| `attachment_error` | 附件失败 | 存在 `error` 附件 | 草稿保留；发送禁用 | 就近展示“上传失败”以及文本“重试/移除”入口，不用新增图标。 |
| `sending` | 发送中 | 创建 Turn 或 Follow-up 请求未完成 | 输入禁用；主操作禁用 | 组件尺寸不跳动；请求失败后恢复输入并保留草稿。 |
| `running_stop` | 运行中、无草稿 | 当前 Turn 为 `queued/in_progress` 且草稿为空 | 输入可用；显示文本“停止” | 停止操作不借用未在 Figma 提供的图标；点击后进入停止中。 |
| `running_queue` | 运行中、有草稿 | 当前 Turn 运行中且草稿存在 | 可编辑；显示“加入队列” | Enter 加入 Follow-up；组合快捷键可立即引导当前运行。 |
| `waiting_input` | 等待用户选择 | Turn 为 `waiting_for_input` | 输入可用；显示等待状态和“停止” | 用户输入请求在消息区回答；普通草稿不被隐式清空。 |
| `stopping` | 停止中 | abort 请求未完成 | 输入可用；停止操作禁用 | 操作文案为“正在停止”，重复点击不会产生第二次请求。 |

验收器同时覆盖 400px 桌面对话栏和 390px 移动视口；全部状态不得产生横向滚动、文字遮挡或因按钮文案切换导致的布局位移。

### 项目画布

| 元素 / 状态 | 规格 |
|---|---|
| 框架 | 白底；顶部 60px，左右 16px；内容 24px；顶部显示当前模式名称与 Figma 全屏/收起图标。 |
| 模式切换 | 底部固定 320px segmented control：设定、章节、作品。外层 `#f7f7f7`，当前项白底和轻阴影。 |
| 设定 | 默认模式。展示“全部/角色/场景/道具”文本筛选；资产卡按可用宽度 2-4 列、16px 间距、1:1 图片、16px 圆角；名称 14px、类型 11px。点击卡片进入现有资产详情。 |
| 章节 | 展示章节顺序、标题、正文/漫画进度与继续编辑入口；空项目提供创建/生成章节的文本入口。 |
| 作品 | 优先展示已定稿或 current 图片及其章节归属；其次展示导出状态和现有导出入口。生成中的卡片保留稳定尺寸并显示状态。 |
| 全屏 | 隐藏中栏对话，画布占用项目区域；再次点击恢复。收起画布时中栏扩展，必须留恢复入口。 |
| 空/加载/错误 | 三种模式分别提供领域化空态；加载卡尺寸固定；单个图片失败用占位符，不导致整页空白；列表请求失败提供文本重试入口。 |

### 响应式

| 视口 | 行为 |
|---|---|
| `>= 1180px` | 完整三栏；画布是主弹性区域。 |
| `760-1179px` | 左栏默认收起；画布单栏展示；对话通过覆盖层打开，URL 与草稿状态不丢失。 |
| `< 760px` | 单一主区域；全局侧栏和对话均使用全高覆盖层；画布卡片 2 列，底部模式切换不超出视口安全区。 |

### 可访问性与稳定性

- 所有图标按钮必须有可访问名称和 hover tooltip；文本入口不得只有颜色表达状态。
- selected、active、`aria-pressed` 与 hover 的组合状态必须显式定义在基础状态之后。
- 交互控件最小点击区域 32px；移动端关键控件不小于 40px。
- 不允许横向页面滚动、文字互相遮挡或动态状态改变固定栏位尺寸。
- 尊重 `prefers-reduced-motion`，进行中加载圈在减弱动画模式下停用旋转但保留状态含义。

## others

### 验收标准

1. 桌面打开任意项目后，视觉顺序为左侧栏、对话栏、项目画布；三栏分别滚动且输入框、画布模式切换固定。
2. 左栏的新对话在有项目和无项目两种状态下均能闭环；搜索、项目折叠、展开更多、置顶、归档、账号设置和 API Key 引导可用。
3. 对话的已有历史、新建、发送、运行中、用户输入请求、附件、错误和空状态均能使用，刷新后 URL 指向的会话可恢复。
4. 画布的设定/章节/作品切换保留对话查询参数；对应真实项目数据可见，空、加载、错误和图片失败状态不破坏布局。
5. Figma 中出现的 Logo、导航、文件夹、状态、附件、发送、全屏、收起等图标，以及示例资产图，均从指定节点导出并保存在前端资产目录，不自行绘制。
6. 在 1440x900、1180x820、390x844 至少三种视口完成浏览器验收；无 console error、无失败网络请求、无横向溢出、无文本重叠。
7. 前端单元测试和生产构建通过；现有公开 API 和后端行为不变。

### 非目标

- 本轮不增加云端注册、团队协作或跨设备已读同步。
- 本轮不重写设定、章节、漫画和导出领域的完整编辑器；只将它们纳入统一画布框架并统一高频入口。
- 本轮不因视觉实现引入 Tailwind、新图标库或新的后端聚合接口。

### 风险与约束

- 当前领域页面信息密度高，不能通过全局 CSS 粗暴缩放；需由工作台容器和模式级组件逐层适配。
- 作品模式横跨漫画 current 图片与导出记录，第一阶段以现有事实投影组合，不能把生成中任务误标为已定稿。
- Figma 原始节点是桌面参考，窄屏行为以本 PRD 的可用性规则为准，同时保持字体、颜色、边框和控件风格一致。
