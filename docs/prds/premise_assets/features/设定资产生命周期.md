# 设定资产 — 设定资产生命周期

## overview

该 Feature 为 Premise 资产提供“active → 回收站 → 恢复或永久删除”的完整生命周期，并把领域删除与底层物理文件回收分离。

- 普通删除设置 `deleted_at` 并增加 `revision`；回收站资源仍保留 variant、tag 和 event。
- 恢复使用 `expected_revision`，重新进入 active 列表，并继续受项目内 active 标题唯一约束。
- 单项永久删除只允许已在回收站的资产。事务先核对 revision，再检查 queued/running 的 Production task、Workflow，以及当前 User Item 或 queued Follow-up 中引用该资产的活动 Chat turn；存在活动使用时整体拒绝。
- 清空回收站按 UUID 稳定扫描所有 trashed 资产。安全项在一个事务中删除，活动项跳过并以 `blocked_items` 返回，因此结果可以是部分成功。
- 删除领域资产会级联 variant、tag 和 event；历史 `chat_context_references.premise_asset_id` 置空，但资源 UUID、快照和 `image_file_id` 保留。每个原 variant File 随后重新检查所有结构化外键与任务、Workflow、Chat Reference、导出、Chapter 快照 JSON 引用；仍被历史使用时保留，否则只设置 `files.deleted_at`。

永久删除不会直接删除 `file_objects` 或磁盘内容。Asset Store 只有在不存在 active、history、trash、snapshot、派生 File 或 pending export 引用且超过 grace period 后，才可通过 dry-run 可审计 GC 回收。

## data_model

生命周期以 `premise_assets.deleted_at` 和 `revision` 为准。`premise_asset_variants.file_id` 使用 `ON DELETE RESTRICT` 保护 File，永久删除领域父记录后才可能逻辑删除无引用 File。

单项和批量操作返回：

- `deleted_count` — 实际永久删除的 Premise 资产数
- `file_soft_deleted_count` — 因无任何保留引用而设置 `files.deleted_at` 的逻辑 File 数
- `retained_file_count` — 因历史或其他业务引用而保留的 File 数
- `blocked_items` — `{uuid, reason}`；当前稳定原因是 `active_task`

所有计数是事务结果，不代表已回收物理 object 或磁盘字节。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/projects/:project_uuid/premise-assets?state=active|trashed` | GET | 返回 `{items}`，按生命周期筛选；可同时使用 tag。 |
| `/api/v1/projects/:project_uuid/premise-assets/:premise_asset_uuid?expected_revision=:revision` | DELETE | 软删除 active 资产。 |
| `/api/v1/projects/:project_uuid/premise-assets/:premise_asset_uuid/restorations` | POST | 以 `expected_revision` 恢复回收站资产。 |
| `/api/v1/projects/:project_uuid/premise-assets/:premise_asset_uuid/permanent?expected_revision=:revision` | DELETE | 永久删除单项；活动任务占用时返回 `production_premise_asset_delete_blocked`。 |
| `/api/v1/projects/:project_uuid/premise-assets/trash` | DELETE | 清空当前项目回收站，返回删除/保留计数和稳定排序的 blocker。 |

所有响应遵守统一 JSON 信封，字段使用 `snake_case`；单项结果直接放在 `data`，列表放在 `data.items`。URL 和 JSON 只公开 UUIDv7，不返回内部 File ID、object ID 或路径。

## ui

| 页面 / 入口 | 说明 |
|---|---|
| `/projects/:project_uuid/premise` 的资产区 | active 与回收站视图分离；回收站支持恢复、单项永久删除和清空。 |
| 永久删除确认 | 明确说明领域记录不可恢复，但仍被快照/历史引用的底层文件会保留；提交中禁止关闭和重复提交。 |
| 清空回收站结果 | 全部成功显示完成提示；存在 `blocked_items` 时显示部分完成，并在刷新后保留被阻止项。 |

## others

成功单删发布 `premise:asset_permanently_deleted`；清空还发布 `premise:trash_emptied`，payload 只含公开资产 UUID或删除/阻止计数。前端同时失效 Premise active/trashed 列表、漫画状态、资产扫描和维护任务查询，使“无 Premise 资产”警告与回收边界及时更新。

物理回收、grace period、dry-run、hash 与 `key_path` 约束以 [`docs/asset-storage.md`](../../../asset-storage.md) 为准。
