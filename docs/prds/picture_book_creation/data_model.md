# 绘本创作 — 内容模型与分页

> 项目共享设定服务于一本或多本绘本；每本绘本以自己的故事、有序页面和画稿形成独立作品。

## 1. 目标

建立适合持续绘本创作的统一内容结构，让用户能清楚理解“项目、绘本、故事简介、完整故事、分页方案和页面”的区别，并让每个阶段的产物都能继续编辑、生成和追溯。

## 2. 核心定义

| 对象 | 回答的问题 | 主要内容 | 是否直接出图/导出 |
|---|---|---|---|
| 项目 | 围绕什么 IP、主题或方向持续创作？ | 项目名称、代表图、创作方向、共享设定和绘本列表 | 否 |
| 共享设定 | 多本绘本中的角色、场景和道具应该保持什么样？ | 项目级角色、场景、道具及版本 | 间接 |
| 绘本 | 这是哪一本可独立完成的作品？ | 绘本名称、可选册序、故事简介、完整故事、页面和画稿 | 是 |
| 完整故事 | 从头到尾具体发生了什么？ | 一份连续可读的故事手稿及版本 | 否 |
| 分页方案 | 这个故事如何分配到每一页？ | 来源故事版本、页面数量、分页节奏和页面草案 | 间接 |
| 页面 | 读者翻到这一页看到什么？ | 页面文字、画面说明、设定引用、画稿与当前使用画面 | 是 |

### 2.1 故事简介

故事简介属于具体绘本，是完整故事的短摘要，帮助用户和 Agent 快速理解这一本讲什么。它不承载完整情节正文，也不直接决定页面数量。

当前仓库中的“剧情简介”/Story Profile 实际包含一句话故事、故事梗概、世界观和重要人物小传，更接近绘本概览信息，不是完整故事。

### 2.2 完整故事

完整故事是分页前的连续手稿。用户应当能从头到尾阅读它，理解事件、转折、对白和结局。它可以使用 Markdown 编写、导入和导出，但 Markdown 标题只负责结构与排版。

### 2.3 分页方案

分页方案是系统或用户对“怎样把完整故事拆到页面”的一次结构化规划。它必须记录基于哪个完整故事版本生成，并产出页面草案。

分页不是在 Markdown 中插入若干标题。正式分页结果必须成为结构化页面，才能可靠支持排序、拆分、合并、单页重做、设定引用、图片版本和导出。

### 2.4 页面

页面是绘本生产和交付的基本单位。每个页面至少包含：

- 页面类型。
- 页面顺序。
- 页面文字，即读者实际看到的文字。
- 画面说明，即构图、动作、情绪、视角和必要视觉信息。
- 引用的角色、场景和道具设定。
- 画稿及当前使用画面。
- 内容版本、保存结果和画稿历史。

## 3. 内容关系

```text
创作项目
├── 项目主页
│   ├── 项目代表图与创作方向
│   ├── 共享设定入口
│   └── 绘本列表
├── 共享设定
│   ├── 角色
│   ├── 场景
│   └── 道具
└── 绘本（一本或多本）
    ├── 名称、可选册序与故事简介
    ├── 完整故事
    │   └── 故事版本
    └── 分页方案
        └── 页面序列
            ├── 封面（可选，最多 1 个）
            ├── 正文页（有序，至少 1 个）
            └── 封底（可选，最多 1 个）
```

项目可以暂时没有绘本；一本绘本只能属于一个项目。设定归属于项目，在设定页集中维护，多本绘本通过公开 `uuid` 引用同一设定，不复制出绘本私有设定库。故事、分页方案、页面、封面、封底和画稿必须归属于具体绘本。

“第 1 册、第 2 册”是绘本的可选排序值，不是内容实体。没有册序的绘本按创建时间升序排在有册序绘本之后；首期不允许一本绘本同时属于多个项目。

## 4. 页面与跨页规则

1. 页面类型包括 `cover`、`body`、`back_cover`。
2. 封面和封底可选，每本绘本最多各一个。
3. 封面位于正文页之前，封底位于正文页之后。
4. 封面和封底不计入正文页数，正文页从 1 开始编号。
5. 正文页至少一个，并保持稳定顺序。
6. 跨页不是页面类型，也不是一级导航对象。
7. 跨页只是两个相邻正文页之间可选的版式关系。
8. 一页不能同时属于两个跨页关系。
9. 调整页序后若两页不再相邻，系统必须解除跨页或要求用户修复。

## 5. 页面画稿与当前使用规则

页面的“是否已有画面”和“有多少画稿”是两个维度，不能混成“待选、已确认、已完成”流程状态。

```text
页面
├── 页面内容
│   ├── 页面文字
│   ├── 画面说明
│   └── 设定引用
└── 画稿
    ├── 第 1 稿
    ├── 第 2 稿（当前使用）
    └── 第 3 稿
```

| 规则 | 产品定义 |
|---|---|
| 首张画面 | 第一张成功生成的画稿自动成为当前使用画面。 |
| 多稿页面 | 只要存在可用画稿，就必须且只能有一稿为当前使用。 |
| 生成新稿 | 新稿加入画稿历史，不替换、不清空当前使用画面。 |
| 切换画稿 | 用户在画稿选择中把另一稿设为当前使用；操作立即生效。 |
| 删除当前稿 | 若还有其他画稿，系统要求选择替代稿或自动回退到上一稿；页面不能长期处于“有稿但无当前画面”。 |
| 生成失败 | 不新增画稿，不改变当前使用画面。 |
| 页面缩略图 | 未生成显示虚线封面和页码；已生成显示当前使用画面和页码。稿数不在缩略图旁展示。 |

## 6. Agent 结构化引用

`@` 是把正式产物加入一次 Agent 请求的引用机制，不创建副本，也不自动执行。

| 引用对象 | 输入框显示 | 发送时提供给 Agent |
|---|---|---|
| 角色“栗栗” | `@栗栗` | 角色公开 `uuid`、当前版本、外观与性格设定。 |
| 道具“月光灯” | `@月光灯` | 道具公开 `uuid`、当前版本、外观与用途。 |
| 场景“沉睡森林” | `@沉睡森林` | 场景公开 `uuid`、当前版本、环境与氛围。 |
| 第 1 页 | `@第1页` | 页面公开 `uuid`、最新页面文字、画面说明、设定引用和当前使用画面。 |

引用只保存公开 `uuid`，Web、API 与实时消息不得暴露数据库内部 `id`。同一条未发送消息中的同一对象只保留一个引用；对象被删除后必须阻止发送并提示用户移除失效引用。

## 7. 核心流程

### 7.1 从简介到完整故事

- 触发：用户已进入具体绘本，并已有创作想法或故事简介。
- 主流程：编辑简介 → Agent 追问 → 生成或编写完整故事 → 用户修订并保存版本。
- 结束状态：形成一份连续可读的当前完整故事。
- 规则：修改简介不能隐式覆盖完整故事；从故事反向更新简介也必须创建明确结果。

### 7.2 从完整故事到分页方案

- 触发：用户在故事模块选择“生成分页方案”。
- 主流程：选择当前故事版本 → 设置必要偏好 → 生成页面草案 → 预览分页节奏 → 采用方案。
- 结束状态：形成有序结构化页面，并记录来源故事版本。
- 异常：生成失败时保留完整故事与已有页面，不产生半套正式页面。

### 7.3 分页后的逐页生产

- 触发：用户进入页面模块。
- 主流程：选择页面 → 编辑页面文字与画面说明 → 引用设定 → 自动保存 → 生成画面或新稿 → 按需切换当前使用画面。
- 结束状态：页面达到可在全书视图检查、全屏阅读或导出的状态。
- 规则：重做一页不能要求重新生成全书；新增画稿不能覆盖历史版本或自动替换当前使用画面。

### 7.4 重新分页

- 触发：用户修改完整故事后再次请求分页。
- 主流程：说明来源版本和影响范围 → 生成新方案 → 比较或确认替换 → 保存结果。
- 规则：已有页面包含人工编辑或当前图片时，不能静默覆盖。

### 7.5 创建绘本

- 触发：用户在项目主页点击“新建绘本”，或在项目 Agent 中确认新建绘本。
- 输入：绘本名称 1 至 80 个 Unicode 字符；创作想法 0 至 2000 个 Unicode 字符。
- 空白创建：只创建绘本对象，进入故事页，不生成完整故事、页面或画面。
- 带想法创建：先创建绘本对象，再基于创作想法生成一份故事初稿；不自动分页或出图。
- 共享内容：新绘本自动获得引用当前项目共享设定的能力，但不会自动把全部设定标记为本册使用。
- 失败：创建失败时保留输入；绘本创建成功而故事生成失败时保留绘本与创作想法，只重试故事生成。

## 8. 功能需求

### 8.1 项目、绘本与设定（P0）

| ID | 功能 | 规则 |
|---|---|---|
| FR-OV-01 | 项目概览 | 项目主页展示项目代表图、名称、创作方向、绘本数量和设定数量。 |
| FR-OV-02 | 绘本列表 | 项目主页展示全部绘本；封面未生成时为虚线，已生成时显示当前使用封面画面。 |
| FR-BOOK-01 | 创建绘本 | 项目主页提供“新建绘本”；只收集名称和可选创作想法。 |
| FR-BOOK-02 | 册序 | 册序为可选排序信息，不创建系列、卷或册实体。 |
| FR-BOOK-03 | 故事简介 | 每本绘本独立保存简短摘要，与完整故事分开。 |
| FR-BOOK-04 | 完整故事入口 | 从绘本卡片或单本工作区进入，不在项目主页展示一个歧义的项目级故事入口。 |
| FR-SET-01 | 共享设定 | 设定页平铺项目级角色、场景、道具，并在项目主页展示最近更新预览。 |
| FR-SET-02 | Agent 引用 | 设定封面支持 `@` 到 Agent 输入框；点击不自动发送。 |

### 8.2 完整故事（P0）

| ID | 功能 | 规则 |
|---|---|---|
| FR-STORY-01 | 连续手稿 | 支持完整故事的编辑、阅读和保存。 |
| FR-STORY-02 | Markdown | 支持 Markdown 编写、导入和导出，但不把标题自动解释为页面。 |
| FR-STORY-03 | 版本 | 保留当前版本与历史版本，分页记录明确来源版本。 |
| FR-STORY-04 | 发起分页 | 提供清晰主操作，并在已有页面时说明影响。 |

### 8.3 分页与页面（P0）

| ID | 功能 | 规则 |
|---|---|---|
| FR-PAGE-01 | 结构化分页 | 分页结果保存为有序页面，而不是只修改故事 Markdown。 |
| FR-PAGE-02 | 页面编辑 | 分别编辑页面文字和画面说明。 |
| FR-PAGE-03 | 页面排序 | 支持插入、删除、复制和调整正文页顺序。 |
| FR-PAGE-04 | 设定引用 | 页面可以引用所属项目的角色、场景和道具，并记录本页实际使用的设定。 |
| FR-PAGE-05 | 画稿版本 | 每页保留多个画稿；存在画稿时必须且只能有一个当前使用画面。 |
| FR-PAGE-06 | 页面类型 | 支持可选封面、正文页和可选封底。 |
| FR-PAGE-07 | 双视图 | 默认逐页编辑，并可切换全书视图按成书顺序检查。 |
| FR-PAGE-08 | 直接生成 | 无画面时生成首稿；已有画面时生成新稿且不替换当前使用画面。 |
| FR-PAGE-09 | Agent 引用 | 当前画面和全书缩略图支持 `@` 页面到 Agent 输入框。 |
| FR-PAGE-10 | 自动保存 | 页面文字与画面说明停止输入 800ms 后保存；生成前必须保存成功。 |

### 8.4 分页增强（P1）

- 页面拆分与合并。
- 多套分页方案长期保留、比较和切换。
- 相邻正文页组成跨页并选择版式。
- 把页面修改按差异生成新的完整故事版本。

## 9. 与当前实现的关系

| 目标概念 | 当前仓库实现 | 产品处理 |
|---|---|---|
| 项目与绘本 | 当前隐含为一项目一本内容 | 目标拆为项目容器与绘本资源；项目、绘本分别使用公开 `uuid`，数据库内部关联继续使用 `bigint id`。 |
| 故事简介 | `project_story_profiles.story_md` 与 `STORY.md` | 目标归属具体绘本，并避免称为完整故事。 |
| 完整故事 | Chapter Story 正文 | 目标改为绘本级连续手稿；迁移方案待技术设计。 |
| 页面 | `comic_sections` | 可复用部分版本能力，但对用户改为页面语义并最终直接归属绘本。 |
| 页面画稿版本 | Storyboard/Image Variant | 保留版本与 current 思路，去除候选确认流程和漫画术语。 |
| 生产快照 | Chapter 漫画快照 | 目标扩展为绘本级分页方案和页面顺序快照。 |

此表只描述迁移方向，不代表目标数据表和 API 已经存在。

## 10. 验收标准

| ID | 场景 | 预期结果 |
|---|---|---|
| AC-01 | 查看项目主页 | 能看到项目创作方向、共享设定和全部绘本，不出现歧义的项目级故事或画面。 |
| AC-02 | 查看完整故事 | 能从头到尾连续阅读，并能识别当前版本。 |
| AC-03 | 执行分页 | 基于明确故事版本产生有序结构化页面。 |
| AC-04 | 修改 Markdown 标题 | 不会隐式增加、删除或重排正式页面。 |
| AC-05 | 编辑单页 | 页面文字、画面说明、设定引用和图片版本分别保存。 |
| AC-06 | 设置封面或封底 | 各自最多一个，且不计入正文页数。 |
| AC-07 | 调整跨页相关页序 | 非相邻关系不会被静默保留。 |
| AC-08 | 重新分页 | 不会静默覆盖人工编辑页面或已采用图片。 |
| AC-09 | 检查一级结构 | 项目下直接包含绘本，不出现独立系列、连载、卷、章节或漫画 Section。 |
| AC-10 | 已有一稿的页面 | 第一稿自动成为当前使用画面，不出现“待选、已确认”状态。 |
| AC-11 | 已有多稿的页面生成新稿 | 新稿加入历史，当前使用画面保持不变。 |
| AC-12 | 页面缩略图 | 未生成是虚线加页码，已生成是当前画面加页码，不显示稿数文字。 |
| AC-13 | `@` 设定或页面 | 正确对象加入当前项目与绘本上下文的 Agent 输入框，且不会自动发送。 |
| AC-14 | 同项目多本绘本 | “月亮邮差”可同时包含“栗栗与月光灯”和“银色信封”，两本绘本共享项目设定，但故事、页面和画稿互不覆盖。 |
| AC-15 | 创建空白绘本 | 只新增绘本对象并进入故事页，不自动生成完整故事、页面或画面。 |
| AC-16 | 创建并生成故事 | 先创建绘本，再生成一次故事初稿；故事生成失败时不会重复创建绘本。 |
| AC-17 | 册序 | 修改“银色信封”的册序只改变项目主页排序，不改变其父项目或内容归属。 |

## 11. 非目标

- 不做独立系列、连载、卷和章节实体；多本绘本直接归属项目。
- 不做出版社、出版批次、发行渠道、上架和读者发布。
- 不用一份 Markdown 同时充当完整故事和权威分页数据。
- 不把跨页设计成独立内容层级。

## 12. 待确认

| 项目 | 当前建议 | 待确认内容 |
|---|---|---|
| 正文页数量 | 产品只要求至少 1 页 | 是否按印刷规格增加偶数页或固定页数校验。 |
| 分页方案历史 | 保留来源版本和方案快照 | 首期是否允许多套方案长期并存。 |
| 页面回写故事 | 必须由用户明确触发 | 生成新故事版本或提供差异合并。 |
| 跨页范围 | 仅相邻正文页 | 印刷内封等特殊页面是否以后纳入。 |
| 绘本归档与恢复 | 首期归档后不出现在默认列表，保留故事、页面与画稿 | 恢复入口与永久删除策略。 |
