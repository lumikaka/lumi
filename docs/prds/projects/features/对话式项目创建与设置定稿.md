# 项目 — 对话式项目创建与设置定稿

## overview

该 Feature 把首页的一行自然语言需求和最多 16 张可选参考图可靠地转换为一个真实但尚未定稿的 local-first 项目，并把原文与有序 File References 作为普通 `conversation` Thread 的首个 User Item 立即交给 Agent。创建流程使用应用库中的持久 Saga 串联参考图清单、默认目录规划、项目库创建、稳定 File 提交、最近项目关联和对话 bootstrap；相同 `idempotency_key`、相同原文与相同有序清单只产生一个项目、一组 File 和一组首轮 Chat 记录，应用启动时可从检查点续跑。

客户端先以 JSON 只声明参考图的顺序、`original_filename`、`mime_type` 和 `byte_size`；附带图片即表示自动用于画面生成，用户只能在发送前移除。服务端为新项固定生成 `reference_role=auto`、文件名标题、空 instruction、`include_in_yolo=true` 和 `plan_source=system_default`，并预分配稳定 Reference、Upload 和 File UUIDv7。旧客户端携带与这组默认完全相同的字段仍可兼容，新 Session 的任何非默认计划以 `project_setup_reference_system_managed` 拒绝；已存在 Session 仅按原文与有序文件元数据验证幂等重放，并保留其历史计划。这些字段只表达视觉用途，不代表 Agent 已读取图片像素，也不会自动改写故事情节。草稿项目建立后，客户端逐项 multipart 上传 PNG、JPEG 或 WebP。File finalize 与 `project_creation_reference_files` 绑定在项目库同一事务提交，应用库再把清单项标记为 `ready`；若进程在两次提交之间退出，启动恢复以项目库绑定为事实校准，不创建第二个 File。全部参考图 ready 前 Session 保持 `awaiting_references`，不会提前创建首轮对话。

新项目以 `setup_status=draft` 开始，目录使用服务端安全占位名，绝不从用户原文拼接路径。Agent 在同一 Run 中读取 Setup、维护唯一的 Setup Draft（初始化草稿/待确认设置），并把原始需求、必要的用户补充和明确标注的 Agent 建议整理到 revisioned `generation_brief`；只有缺失或冲突会显著影响首章时，才通过 `request_user_input` 一次询问 1～3 个相关的普通问题。Agent 只需 PATCH 完整 Setup 并展示字段来源、视觉参考数量与自动使用说明、Brief 和准确产出范围。Setup 进入 `pending_confirmation` 后，运行时在下一次模型请求前自动持久化并执行 finalization Tool Intent，不生成危险操作确认卡。这个免确认例外只接受带不可伪造内部标记、绑定当前 bootstrap creation session 的运行时请求；模型不调用 finalization 或 Workflow route。初始化阶段不得创建、选择或切换 Candidate；Candidate 只用于追加式版本及选择、恢复、回滚场景。

运行时 finalization 在项目库单事务内写入项目名、生成语言、默认画风、唯一正式绘本规格和 Setup 终态，再把项目切换为 `ready`；定稿不改写参考计划。finalization 成功后，运行时在再次调用模型前直接从已定稿 `generation_brief` 持久化并执行唯一 `yolo_project_initialization` Workflow Intent。普通 Agent 发起的 finalization 和其他危险操作仍走全局确认协议，不继承 bootstrap 例外。

草稿期只开放项目事实读取、当前对话和 Project Setup 的读取/更新/定稿。Chapter、Story、图片、Workflow、生产、维护和导出入口在 HTTP、Agent 工具、Service 与 Worker 边界都以 `project_setup_incomplete` 拒绝，避免绕过 UI 或由已入队任务越权执行。首个 Turn 使用 origin bootstrap 身份；后续 Turn 不继承普通生产权限，但运行时可在用户明确输入“继续/开始生成/重试生成”时，用不可伪造的 thread lineage、成功 finalization execution UUID 和 creation session UUID 恢复未完成转移。普通后续 Turn 不会因历史 bootstrap 自动启动生产。实时事件只是变更提示，客户端始终通过 REST 重读 SQLite 事实。

## data_model

```text
应用库
project_creation_sessions ──> recent_projects
          └──< project_creation_session_references
                         │ 稳定 upload_uuid / file_uuid
                         ▼
项目库
projects(setup_status=draft)
   ├──1 project_setup_drafts
   ├──0..16 project_creation_reference_files ──> files
   └──1 project_creation_bootstraps ──> conversation thread ──> first turn/run/item/job
                                                              └──< chat_context_references

finalize transaction
project_setup_drafts(finalized) + project_picture_book_profiles(唯一、不可变)
                              + projects(setup_status=ready)
```

`project_creation_sessions` 使用内部自增 `id`，外部以 UUIDv7 `uuid` 标识；`idempotency_key` 全局唯一。无参考图时状态依次为 `pending → creating_project → creating_conversation → active`；有参考图时在项目建立后进入 `awaiting_references`，全部完成后才进入 `creating_conversation`。任一步可进入 `failed`，重试从已持久化的 `planned_root_path`、`recent_project_id`、项目 File 绑定或 bootstrap 唯一记录继续。原始输入保存在 `input_text`，不得改写或用于目录名。

`project_creation_session_references` 以内部 `project_creation_session_id` 归属 Session，以 1–16 的 `position` 固定用户顺序。每项保存公开 Reference UUIDv7、预分配且唯一的 `upload_uuid` / `file_uuid`、声明文件元数据、历史兼容计划字段及 `pending|uploading|ready|failed` 状态。新写入固定为 `auto`、文件名标题、空 instruction、included 和 `system_default`；历史自定义值原样保留。相同幂等键的重放必须匹配原文与有序文件元数据，否则返回 `project_creation_idempotency_conflict`；重放不使用客户端计划字段改写已存事实。

项目库的 `project_creation_reference_files` 使用自己的公开 binding UUIDv7，通过 `creation_session_uuid` / 内部来源 `reference_uuid` 与应用库对应，并以内部 `file_id` 关联 `files.id`。它保存 Project Setup 的计划事实，以及可空 `premise_asset_id` 与 `imported_at`。`reference_uuid`、`file_id`、非空 `premise_asset_id` 和 `(creation_session_uuid, position)` 均唯一；File finalize 与绑定同事务，绑定存在即表示该清单项可以恢复为 ready。创建绑定也属于 Asset GC 的结构化保留来源。

`projects.setup_status` 为 `draft|ready`。迁移前项目与既有手动创建流程默认为 `ready`，所以升级不要求补建 Setup Draft。对话式项目创建 `project_setup_drafts` 唯一记录：公开 `uuid`、原始输入、草稿值、最长 4000 字符的 `generation_brief`、规范化绘本字段、`revision`、缺失字段和字段来源。新草稿默认从修剪后的 `original_input` 生成 Brief；迁移也以相同规则回填历史记录并标记 `system_default`。草稿状态为 `draft|pending_confirmation|finalized|failed`；来源为 `system_default|agent_proposed|user_confirmed`。公开 JSON 使用 `draft_values`，不提供 `candidate` 兼容别名。

`project_creation_bootstraps.creation_session_uuid` 唯一，且 `thread_id`、`turn_id` 分别唯一。bootstrap 在一个项目库事务中写入普通 Thread、首个 Turn、User Item、按清单顺序解析的 `chat_context_references`、Run、队列 Job 和该唯一记录；任意中间写入、Reference 解析或入队失败都会整体回滚。

该记录同时提供首次 Turn 的 origin bootstrap 身份和整个 Thread 的恢复 lineage。finalization 与 Workflow Intent 由运行时以确定性 Provider call ID 生成，并在 Tool Execution 同一事务写入内部来源标记；模型 schema 不允许伪造这些字段。受审 YOLO route 使用服务端生成的 `project-creation-yolo:<creation_session_uuid>`，并要求内部 session 与精确的成功 finalization execution UUID 同时匹配；模型不能提交 title、Provider、幂等键、Chapter 数或 Section 数。Tool 恢复、进程重启和队列重投都只能恢复项目内同一个 Workflow；升级前已进入旧确认流程的持久化记录继续兼容恢复。

正式 `project_picture_book_profiles` 在草稿期必须为零行，定稿后恰好一行。现有 UPDATE 和新增 DELETE trigger 共同保证正式规格不可变。finalization 保存 `finalized_revision`，同 revision 重放返回既有结果，不同或过期 revision 返回 `project_setup_revision_conflict`。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/project-creation-sessions` | POST | 接受原始 `input_text`、稳定 `idempotency_key` 和有序 `reference_files[{original_filename,mime_type,byte_size}]`；服务端生成系统托管计划并创建或恢复 Saga。旧客户端的等价默认字段可兼容，非默认新写入返回 `project_setup_reference_system_managed`。最多 16 张，每张 32 MiB，只允许 PNG/JPEG/WebP。 |
| `/api/v1/project-creation-sessions/:session_uuid` | GET | 返回公开状态、项目/Thread/Turn UUID、`references` 有序状态和可展示错误；仅 ready 项返回 `file_uuid`，不暴露路径、Upload UUID 或内部 ID。 |
| `/api/v1/project-creation-sessions/:session_uuid/retries` | POST | 从持久检查点幂等重试失败或中间态 Session。 |
| `/api/v1/project-creation-sessions/:session_uuid/references/:reference_uuid/uploads` | POST | 以字段名 `file` 的 multipart 单图上传固定清单项；复用预分配 Upload/File 身份，成功后自动恢复 Session，最后一张可直接返回 `active`。 |
| `/api/v1/projects/:project_uuid/project-setup` | GET | 读取原始输入、`draft_values`、字段来源、缺失信息、revision、正式规格和 `reference_plan.items`；每项只含公开 binding/File/Premise UUID、缩略图 URL 与计划。 |
| `/api/v1/projects/:project_uuid/project-setup` | PATCH | 用 `expected_revision` 更新 Setup Draft 和 `generation_brief`；服务端规范化绘本形式、比例和专属字段，调用方不能伪造 provenance。 |
| `/api/v1/projects/:project_uuid/project-setup/references/:reference_uuid` | PATCH | 保留一个版本的兼容边界，不再修改数据，统一返回 `project_setup_reference_system_managed`。该路由不在 Agent Route Registry 中。 |
| `/api/v1/projects/:project_uuid/project-setup-finalizations` | POST | 用 `expected_revision` 定稿完整 Setup Draft；普通 Agent 请求属于危险操作，确认卡及原请求重放由运行时管理；可信 bootstrap 运行时请求免确认。 |
| `/api/v1/projects/:project_uuid/workflows` | POST | 对话式 bootstrap 由运行时从已定稿 `generation_brief` 生成内部请求；服务端绑定项目名、当前 Run 和创建会话幂等键并启动既有 YOLO。 |

所有响应遵守统一 snake_case JSON 信封。输入/幂等冲突、Reference 不存在或未就绪、设置不完整、revision 冲突和无效 Setup Draft 分别使用稳定错误码；外部仅返回 UUIDv7。

## ui

| 页面 / 入口 | 说明 |
|---|---|
| `/` | 新建项目只展示通用附件条、缩略图和发送前移除能力，不展示用途、名称、说明或参与参数。提交时在 `sessionStorage` 保存输入、有序文件元数据、幂等键和已知 Session UUID；创建后锁定 manifest，刷新以服务端响应校准。选择已有项目时仍走普通 Chat Reference。 |
| `/projects/:project_uuid?chat_thread_uuid=:thread_uuid` | 创建成功后直接打开该普通对话。桌面展开 ChatArea，紧凑布局显示覆盖层；`draft` 时隐藏创作工作台主标签。 |
| ChatArea Project Setup Card | 只读展示参考图缩略图，并说明“已附带 N 张视觉参考，将自动用于画面生成”；不提供参考计划控件、保存按钮或 included 计数。 |
| ChatArea 自动生成卡片 | Workflow 以内联卡片显示在 bootstrap 来源 Turn 内，保持原 conversation Thread 标题；`workflow_uuid` 只定位卡片与诊断，不切换到其他 Thread。 |

## jobs

| Job / Worker | 触发条件 | 策略 |
|---|---|---|
| 首个 Agent Run | Chat bootstrap 事务完成 | 与 Thread/Turn/Run/Item 同事务恰好一次入队；Agent 可在同一 Run 中观察 finalization 后的 `ready` 状态。 |
| 自动生成 Workflow | Setup 完整且运行时 finalization 成功 | 不经过第二次 LLM 请求或确认卡，在当前 Turn 内创建 `yolo_project_initialization`、Steps、await 与首步 Job；释放 Agent worker，终态后唯一恢复同一 Run。明确恢复可在后续 Turn 复用同一 creation session。 |
| 创建 Saga 启动恢复 | Server 启动 | 顺序扫描 `pending|creating_project|awaiting_references|creating_conversation|failed` Session；先用项目创建绑定校准参考图状态，再按持久检查点续跑。唯一键防止重复项目、File、Reference 或首轮。 |
| 业务 Worker 门禁 | 任意任务执行前 | 重新读取项目 `setup_status`；`draft` 任务取消并记录稳定错误，不能依赖入队时状态。 |

## others

应用库和项目库无法组成跨库事务，因此 Saga 先在应用库原子创建 Session 与参考图清单，再规划 UUID/路径、写 `recent_project_id`、逐项提交稳定 File 绑定，最后写 Chat bootstrap。项目库内部的 File finalize + 创建绑定、Chat bootstrap + 首条 References 与最终定稿分别保持严格单事务原子性。

`project:setup_changed` 使用 `/api/v1/ws` 的项目 topic 广播，只含 `project_uuid`、`setup_uuid`、`status`、`setup_status` 和 `revision`。TanStack Query 收到提示后失效 Setup、项目详情和最近/打开项目查询；首次 join、重新 join和窗口重新聚焦也通过 REST 校准，不使用定时 HTTP 轮询。

创建 Saga 在 `system` topic 发送 `project_creation_session:changed` 变更提示，只含 `session_uuid`、状态及已经存在的项目/Thread UUIDv7。首页收到提示后失效精确 Session 查询，并通过 REST 重读应用库事实；首次 join、重新 join、窗口聚焦或重新可见时也校准，不把实时 payload 当作业务事实。

非阻塞限制：最终项目名不会重命名已创建的安全占位目录；当前 Session 串行推进由进程内互斥保护，数据库唯一键负责跨重试正确性；`cancelled` 状态已在模型中保留，但本 Feature 暂未提供取消 API。

本流程不新增 Initial Preview 或第二套生成器。YOLO 的范围保持为唯一 `vol01.ch01` 和 1～6 个 `body` Comic Sections；新建普通绘本输入快照还会创建或复用唯一 `front_cover`，并默认生成封面与第一张正文页的 current image；`vertical_strip` 只生成第一个 `body` 的 current image。Premise Setting Image 仍属于既有设定步骤。Workflow 创建失败时当前 Turn 报告安全错误并停止，不回退到手工生产。

参考计划字段继续作为历史与生产快照事实，但不再是用户可编辑设置；定稿不将 `system_default` 改为 `user_confirmed`。新图全部进入来源 Premise Asset、参考板和 Provider 图片输入；历史 included/excluded 值继续按原事实生产。图片缺失、损坏或 Provider 拒绝图片输入时，当前 Workflow 步骤以稳定错误失败并允许重试，不静默降级为纯文本。
