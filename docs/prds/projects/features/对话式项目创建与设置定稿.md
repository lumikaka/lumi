# 项目 — 对话式项目创建与设置定稿

## overview

该 Feature 把首页的一行自然语言需求可靠地转换为一个真实但尚未定稿的 local-first 项目，并把原文作为普通 `conversation` Thread 的首个 User Item 立即交给 Agent。创建流程使用应用库中的持久 Saga 串联默认目录规划、项目库创建、最近项目关联和对话 bootstrap；相同 `idempotency_key` 与相同输入只产生一个项目和一组首轮 Chat 记录，应用启动时可从检查点续跑。

新项目以 `setup_status=draft` 开始，目录使用服务端安全占位名，绝不从用户原文拼接路径。Agent 在同一 Run 中读取 Setup、提取候选，并把原始需求、必要的用户补充和明确标注的 Agent 建议整理为 YOLO Brief；只有缺失或冲突会显著影响首章时，才通过 `request_user_input` 一次询问 1～3 个相关问题。Agent 展示候选、字段来源、Brief 和准确产出范围后，以稳定 `question_id=confirm_setup_and_start_yolo` 请求确认，第一项“继续修改”为安全推荐项，第二项明确为“定稿并启动 YOLO”。

只有用户明确选择确认项，运行时才按既有 fingerprint-bound 协议自动重放危险级 finalization。定稿在项目库单事务内写入项目名、生成语言、默认画风、唯一正式绘本规格和 Setup 终态，再把项目切换为 `ready`；同一 bootstrap Run 随后只能创建现有 `yolo_project_initialization` Workflow。选择安全项、Other、取消或仅要求定稿都不会隐式启动 YOLO。

草稿期只开放项目事实读取、当前对话和 Project Setup 的读取/更新/定稿。Chapter、Story、图片、Workflow、生产、维护和导出入口在 HTTP、Agent 工具、Service 与 Worker 边界都以 `project_setup_incomplete` 拒绝，避免绕过 UI 或由已入队任务越权执行。项目 ready 后，只有 `project_creation_bootstraps.turn_id` 指向的首次 Turn 继续受专用门禁：GET、已确认 finalization 的恢复和已授权 YOLO 创建可用，其他写请求与 `image_gen` 返回 `bootstrap_production_requires_yolo`；后续 Turn 不继承限制。实时事件只是变更提示，客户端始终通过 REST 重读 SQLite 事实。

## data_model

```text
应用库
project_creation_sessions ──> recent_projects
          │ 公开 creation_session_uuid
          ▼
项目库
projects(setup_status=draft)
   ├──1 project_setup_drafts
   └──1 project_creation_bootstraps ──> conversation thread ──> first turn/run/item/job

finalize transaction
project_setup_drafts(finalized) + project_picture_book_profiles(唯一、不可变)
                              + projects(setup_status=ready)
```

`project_creation_sessions` 使用内部自增 `id`，外部以 UUIDv7 `uuid` 标识；`idempotency_key` 全局唯一。状态依次为 `pending → creating_project → creating_conversation → active`，任一步可进入 `failed`，重试从已持久化的 `planned_root_path`、`recent_project_id` 或 bootstrap 唯一记录继续。原始输入保存在 `input_text`，不得改写或用于目录名。

`projects.setup_status` 为 `draft|ready`。迁移前项目与既有手动创建流程默认为 `ready`，所以升级不要求补建 Setup Draft。对话式项目创建 `project_setup_drafts` 唯一记录：公开 `uuid`、原始输入、候选资料、规范化绘本字段、`revision`、缺失字段和字段来源。候选状态为 `draft|pending_confirmation|finalized|failed`；来源为 `system_default|agent_proposed|user_confirmed`。

`project_creation_bootstraps.creation_session_uuid` 唯一，且 `thread_id`、`turn_id` 分别唯一。bootstrap 在一个项目库事务中写入普通 Thread、首个 Turn、User Item、Run、队列 Job 和该唯一记录；任意中间写入或入队失败都会整体回滚。

该记录也是首次 Turn 的可信授权和幂等来源。运行时只在当前 `turn.id` 命中时注入进程内 bootstrap 标记；受审 YOLO route 使用服务端生成的 `project-creation-yolo:<creation_session_uuid>`，模型不能提交 title、Provider、幂等键、Chapter 数或 Section 数。同一 Turn、Tool 恢复或不同 Brief 重放都返回项目内同一个 Workflow。

正式 `project_picture_book_profiles` 在草稿期必须为零行，定稿后恰好一行。现有 UPDATE 和新增 DELETE trigger 共同保证正式规格不可变。finalization 保存 `finalized_revision`，同 revision 重放返回既有结果，不同或过期 revision 返回 `project_setup_revision_conflict`。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/project-creation-sessions` | POST | 接受原始 `input_text` 与稳定 `idempotency_key`，预检可用文本模型后创建或恢复 Saga；返回创建会话资源。 |
| `/api/v1/project-creation-sessions/:session_uuid` | GET | 返回公开状态、项目/Thread/Turn UUID 和可展示错误，不暴露路径或内部 ID。 |
| `/api/v1/project-creation-sessions/:session_uuid/retries` | POST | 从持久检查点幂等重试失败或中间态 Session。 |
| `/api/v1/projects/:project_uuid/project-setup` | GET | 读取原始输入、候选、字段来源、缺失信息、revision 和正式规格。 |
| `/api/v1/projects/:project_uuid/project-setup` | PATCH | 用 `expected_revision` 更新候选；服务端规范化绘本形式、比例和专属字段，调用方不能伪造 provenance。 |
| `/api/v1/projects/:project_uuid/project-setup-finalizations` | POST | 用 `expected_revision` 定稿完整候选；Agent 路由要求显式危险操作确认。 |
| `/api/v1/projects/:project_uuid/workflows` | POST | 定稿后的首次 Run 通过严格 Agent overlay 只提交 `story_prompt` 和可选模型；服务端绑定项目名、当前 Run 和创建会话幂等键并启动既有 YOLO。 |

所有响应遵守统一 snake_case JSON 信封。输入/幂等冲突、设置不完整、revision 冲突和非法候选分别使用稳定错误码；外部仅返回 UUIDv7。

## ui

| 页面 / 入口 | 说明 |
|---|---|
| `/` | 项目列表上方展示一行需求 Composer。提交时在 `sessionStorage` 保存输入、幂等键和已知 Session UUID；重复点击禁用，刷新后以 GET 或同键 POST 恢复，失败态提供显式重试。 |
| `/projects/:project_uuid?chat_thread_uuid=:thread_uuid` | 创建成功后直接打开该普通对话。桌面展开 ChatArea，紧凑布局显示覆盖层；`draft` 时隐藏创作工作台主标签。 |
| ChatArea Project Setup Card | 展示候选项目名、语言、画风、绘本形式、比例、专属选项、缺失项、来源与 revision；定稿后保留为已完成记录。 |
| ChatArea YOLO 引用 | Workflow 创建成功后，bootstrap Turn 使用服务端返回的 `@project/workflows/{workflow_uuid}`；客户端选中其 dedicated Thread，不强制跳转或等待终态。 |

## jobs

| Job / Worker | 触发条件 | 策略 |
|---|---|---|
| 首个 Agent Run | Chat bootstrap 事务完成 | 与 Thread/Turn/Run/Item 同事务恰好一次入队；Agent 可在同一 Run 中观察 finalization 后的 `ready` 状态。 |
| YOLO Workflow | 用户在首个 Run 明确选择“定稿并启动 YOLO”且 finalization 成功 | 只创建 existing YOLO 并立即结束 bootstrap Turn；不得轮询终态或手工模拟 Story、Premise、Chapter、Section 与图片步骤。 |
| 创建 Saga 启动恢复 | Server 启动 | 顺序扫描 `pending|creating_project|creating_conversation|failed` Session，按持久检查点续跑；唯一键防止重复项目或重复首轮。 |
| 业务 Worker 门禁 | 任意任务执行前 | 重新读取项目 `setup_status`；`draft` 任务取消并记录稳定错误，不能依赖入队时状态。 |

## others

应用库和项目库无法组成跨库事务，因此 Saga 以先规划 UUID/路径、再写 `recent_project_id`、最后写 Chat bootstrap 的持久检查点保证可恢复；项目库内部的 Chat bootstrap 与最终定稿各自保持严格单事务原子性。

`project:setup_changed` 使用 `/api/v1/ws` 的项目 topic 广播，只含 `project_uuid`、`setup_uuid`、`status`、`setup_status` 和 `revision`。TanStack Query 收到提示后失效 Setup、项目详情和最近/打开项目查询；首次 join、重新 join和窗口重新聚焦也通过 REST 校准，不使用定时 HTTP 轮询。

非阻塞限制：最终项目名不会重命名已创建的安全占位目录；当前 Session 串行推进由进程内互斥保护，数据库唯一键负责跨重试正确性；`cancelled` 状态已在模型中保留，但本 Feature 暂未提供取消 API。

本流程不新增 Initial Preview 或第二套生成器。YOLO 的既有范围保持为唯一 `vol01.ch01`、1～6 个 Comic Sections，并只为第一个 Section 生成漫画 current image；Premise Setting Image 仍属于既有设定步骤。Workflow 创建失败时当前 Turn报告安全错误并停止，不回退到手工生产。
