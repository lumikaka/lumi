# 文件 — 资产完整性扫描与修复

## overview

该 Feature 检查 Asset Store 中对象的存在性、hash、缩略图和隔离状态，并在项目打开或用户请求时执行受控 reconcile。扫描结果持久化为可分页读取的 Scan 和 Finding，避免把一次性磁盘遍历结果作为不可追溯的 UI 消息。

## data_model

`integrity_scans` 记录 `light|full` 模式、状态、进度、检查数量、finding 数量和安全摘要；每项目每种模式最多一个 queued/running Scan。`integrity_findings` 保存可选 Object 内部关联、`pending|missing|corrupt|quarantined|orphan|thumbnail` 类型、严重度、受控路径摘要和 `open|reconciled|quarantined|ignored|removed` 处理状态。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/projects/:project_uuid/integrity-scans` | GET / POST | 查询历史或创建 light/full 扫描。 |
| `/api/v1/projects/:project_uuid/integrity-scans/:scan_uuid` | GET | 读取扫描、摘要与 Findings。 |
| `/api/v1/projects/:project_uuid/asset-reconciliations` | POST | 创建受控 reconcile。 |

## ui

| 页面 / 入口 | 说明 |
|---|---|
| `/projects/:project_uuid/assets` | 显示扫描进度、问题摘要、受控修复状态和重新扫描入口。 |

## others

项目打开时 reconciliation 有上限，不能把未验证的磁盘路径直接作为 API 资源。事件只发布公开 UUIDv7、状态和刷新提示。
