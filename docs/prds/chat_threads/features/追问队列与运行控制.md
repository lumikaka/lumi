# 对话线程 — 追问队列与运行控制

## overview

该 Feature 让用户在当前 Agent Run 执行时继续排队追问，并可在允许的并发窗口把单条 Follow-up 立即提升为 steering。服务端在事务中判断是提升为当前运行引导还是保留 queued，避免前端依据瞬时状态产生竞态。

用户也可以取消当前 Thread 执行；取消请求持久化后由运行时中断 Provider context 并在提交业务结果前再次检查持久状态。

## data_model

`chat_follow_ups` 以 Thread 内 position 排序，状态为 `queued`、`promoted` 或 `deleted`，可选关联 `promoted_turn_id`；其 `chat_context_references` 在提升为 Turn 或 Steering 时原子迁移到新 User Item。Turn 和 Run 分别记录取消时间及 `queued|running|waiting_for_input|completed|failed|cancelled|interrupted` 等状态。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/follow_ups` | GET / POST | 读取或以 `input_text`、`references` 创建排队追问。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/follow_ups/:follow_up_uuid` | PATCH / DELETE | 编辑或删除；PATCH 省略 `references` 为保留，空数组为清空，非空数组为原子替换。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/follow_ups/:follow_up_uuid/position` | PATCH | 重排队列位置。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/follow_ups/:follow_up_uuid/steerings` | POST | 尝试立即引导当前运行。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/steerings` | POST | 对当前运行发送带独立 Reference 的 steering。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/cancellations` | POST | 请求停止当前执行。 |

## ui

| 页面 / 入口 | 说明 |
|---|---|
| ChatArea 输入区与追问队列 | 支持排队、Reference 展示、编辑时保留、删除、拖拽或键盘重排、携带 Reference 立即引导和停止。 |

## others

运行中没有可提升窗口时，Follow-up 保持 queued 并返回稳定状态。不能依赖定时轮询判断任务是否完成。
