# 对话线程 — 对话工具与多模态交互

## overview

该 Feature 把 Agent 工具调用、用户选择题和多资源 Reference 变成可恢复的对话交互。工具先写入 `agent_tool_executions` 意图和幂等键，再由受控项目 API 或图片生成能力执行；用户输入请求通过持久状态暂停和恢复 Run，不把临时浏览器状态当作事实源。活动 `project_api_v4` 的 `request_user_input` 一次包含 1–3 个短问题，每题只有 2–3 个互斥选项，第一项带精确的 ` (Recommended)` 后缀；Other 由客户端统一提供。该工具仍必须是模型当次响应中的唯一 Tool Call。

初始 Turn、Steering 和 Follow-up 均可携带最多 16 个 `file`、`premise_asset`、`chapter` 或 `comic_section` Reference。Reference 只属于对应用户输入；普通新 Turn 从空集合开始，历史 Reference 不会重新注入。Chapter 工作台点击 ChatArea 的“新建会话”时预选当前公开 Chapter UUID，用户可在发送前移除；当前 Turn 中同一资源再次出现时，以最新 User Item 的冻结快照为准。

## data_model

`chat_user_input_requests` 关联 Thread、Run、Turn、Item 和 Tool call UUID，以 `schema_version` 区分 `codex_questions_v1` 与 `legacy_choice_v1`，并用唯一事实列 `request_json` 保存请求；`response_json` 保存浏览器提交的 question-id → 选项 UUID/Other 映射和 `pending|answered|resuming|resumed|cancelled` 状态。v4 每题的选项 UUIDv7 由服务端生成，服务端校验后才把回答转换为模型可见的 `{answers:{question_id:{answers:[label_or_text]}}}`。`agent_tool_executions` 保存工具名、目标 UUID、合法 JSON 参数、幂等键、执行状态和脱敏结果。`chat_context_references` 以内部 owner/资源/File 外键关联，公开投影只含资源类型、UUID、位置、`image_available` 和紧凑快照。`comic_section` 快照的 `page_role` 与 `body_page_no` 是 Agent 面向用户区分封面、正文页和封底的事实，不得把绝对 `section_no` 直接当作正文页码。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/user_input_requests` | GET | 读取 Thread 的用户输入请求。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/user_input_requests/:request_uuid/responses` | POST | v4 以 question id 映射提交每题一个选项 UUID 或 Other；v2/v3 历史请求继续接受冻结的单选/多选回答。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/user_input_requests/:request_uuid/cancellations` | POST | 取消待回答请求。 |
| `/api/v1/projects/:project_uuid/asset-uploads` | POST | 为图片引用创建受控上传。 |
| `/api/v1/projects/:project_uuid/asset-uploads/:upload_uuid/completions` | POST | 完成上传并获得可引用 File。 |

## ui

| 页面 / 入口 | 说明 |
|---|---|
| ChatArea 工具与输入项 | 待答卡片逐题显示 header、问题、推荐标记、互斥选项和 Other，全部回答后一次提交；历史卡片逐题展示最终答案，并兼容旧单选、多选和 Other。统一 Reference Strip 与 Picker；可选择 Chapter、Premise Asset 和按 Chapter 筛选的 Comic Section，并依 `page_role` 显示封面、正文页或封底，图片先 finalize 为 File Reference。 |
| Chapter / Premise / Comic 入口 | Chapter 工作台新会话自动预选当前 Chapter；其他业务入口可预选资源 Reference，均不创建绑定资源的特殊 Thread。 |

## others

危险 Route 的 v4 confirmation 只允许绑定一个问题和匹配的 `question_id`；第一项必须是安全推荐项，`confirm_option` 必须指向后续明确危险选项。只有该问题选中绑定的服务端 UUID 才授权操作，安全项、Other、错题、错目标、错 revision 或错 fingerprint 均不授权。v2/v3 按冻结的旧绑定语义恢复。

`image_gen.reference_uuids` 是必填数组，可为空，最多按顺序选择 4 个当前 Turn 中具有冻结图片的 Reference；历史、未知、重复或无图项返回可修复 validation 错误。结果使用普通 Chat 图片用途，并记录来源 Reference UUID、类型和实际 File UUID。对外 Item metadata、事件与工具结果递归移除内部 `id`、路径、Authorization、cookie、credential、password、API key 和 token。
