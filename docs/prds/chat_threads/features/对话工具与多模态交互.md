# 对话线程 — 对话工具与多模态交互

## overview

该 Feature 把 Agent 工具调用、用户选择题和多资源 Reference 变成可恢复的对话交互。工具先写入 `agent_tool_executions` 意图和幂等键，再由受控项目 API 或图片生成能力执行；用户输入请求通过持久状态暂停和恢复 Run，不把临时浏览器状态当作事实源。活动 `project_api_v4` 的模型可见 `request_user_input` schema 只包含 `questions`：一次 1–3 个短问题，每题只有 2–3 个互斥选项，第一项带精确的 ` (Recommended)` 后缀；Other 由客户端统一提供。该工具仍必须是模型当次响应中的唯一 Tool Call。`confirmation` 不属于模型工具协议；任何顶层或嵌套的模型传入均在形成 Tool Intent 前拒绝。

初始 Turn、Steering 和 Follow-up 均可携带最多 16 个 `file`、`premise_asset`、`chapter` 或 `comic_section` Reference。每次引用都保留对应用户输入创建时的冻结快照；普通新 Turn 的显式 Reference 集合仍从空集合开始，但模型会收到当前 Thread 最近可用的历史图片 Reference 紧凑清单，`image_gen` 可以继续按 `resource_uuid` 选择它们。Chapter 工作台点击 ChatArea 的“新建会话”时预选当前公开 Chapter UUID，用户可在发送前移除；当前 Turn 中同一资源再次出现时，以最新 User Item 的冻结快照为准，否则使用当前 Thread 中最近的历史冻结快照。

## data_model

`chat_user_input_requests` 关联 Thread、Run、Turn、Item 和 Tool call UUID，以 `schema_version` 区分 `codex_questions_v1` 与 `legacy_choice_v1`，并用唯一事实列 `request_json` 保存请求；`response_json` 保存浏览器提交的 question-id → 选项 UUID/Other 映射和 `pending|answered|resuming|resumed|cancelled` 状态。v4 每题的选项 UUIDv7 由服务端生成，服务端校验后才把普通问题回答转换为模型可见的 `{answers:{question_id:{answers:[label_or_text]}}}`。`agent_tool_executions` 保存工具名、目标 UUID、合法 JSON 参数、幂等键、执行状态和脱敏结果。运行时危险确认的内部参数额外带 `__runtime_generated_confirmation=true` 与 `__confirmation_source_execution_uuid`，后者必须指向同一 Run 中已持久化、确实返回 `agent_tool_confirmation_required` 的 `request_api` Execution。`chat_context_references` 以内部 owner/资源/File 外键关联，公开投影只含资源类型、UUID、位置、`image_available` 和紧凑快照。`comic_section` 快照的 `page_role` 与 `body_page_no` 是 Agent 面向用户区分封面、正文页和封底的事实，不得把绝对 `section_no` 直接当作正文页码。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/user_input_requests` | GET | 读取 Thread 的用户输入请求。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/user_input_requests/:request_uuid/responses` | POST | v4 以 question id 映射提交每题一个选项 UUID 或 Other；v2/v3 历史请求继续接受冻结的单选/多选回答。 |
| `/api/v1/projects/:project_uuid/chat_threads/:thread_uuid/user_input_requests/:request_uuid/cancellations` | POST | 取消待回答请求。 |
| `/api/v1/projects/:project_uuid/asset-uploads` | POST | 为图片引用创建受控上传。 |
| `/api/v1/projects/:project_uuid/asset-uploads/:upload_uuid/completions` | POST | 完成上传并获得可引用 File。 |

## ui

| 页面 / 入口 | 说明 |
|---|---|
| ChatArea 工具与输入项 | 待答卡片逐题显示 header、问题、推荐标记、互斥选项和 Other，全部回答后一次提交；历史卡片逐题展示最终答案，并兼容旧单选、多选和 Other。统一 Reference Strip 与 Picker；可选择 Chapter、Premise Asset 和按 Chapter 筛选的 Comic Section，并依 `page_role` 显示封面、正文页或封底，图片先 finalize 为 File Reference。 |

## others

危险 Route 先完整执行一次 `request_api`。当结果为 `agent_tool_confirmation_required` 时，运行时在同一 Tool Result 事务中持久化规范确认意图并暂停 Run：v4 使用唯一 questions 卡，v2/v3 及必要的 legacy 恢复运行使用冻结的旧卡片协议。安全项、Other、取消、错目标、错 revision 或错 fingerprint 均不执行；只有确认项会从来源 Execution 的持久化参数生成一个确定性幂等 replay Intent。重复回答、进程重启和队列重投只恢复同一 replay。升级恢复在每次模型调用前扫描无确认意图的旧 confirmation-required 结果，并按来源 Execution UUID 幂等补建；旧嵌套形状修复只用于读取历史记录。

`image_gen.reference_uuids` 是必填数组，可为空，最多按顺序选择 4 个当前 Thread 中截至本次调用前出现过且具有冻结图片的 Reference；当前 Turn 的同一资源优先，否则选择最近的历史冻结快照。其他 Thread、未知、重复或无图项返回可修复 validation 错误。`edit`/`restyle` 的第一项是内容来源；必要内容 Reference 不可用或被拒绝时不得降级为 `generate`。结果使用普通 Chat 图片用途，并记录操作类型、来源 Reference UUID、类型和实际 File UUID。对外 Item metadata、事件与工具结果递归移除内部 `id`、路径、Authorization、cookie、credential、password、API key 和 token。
