# 故事生产 — 章节生命周期

## overview

该 Feature 管理 Chapter 从 active 到回收站、恢复或永久删除的完整生命周期。普通删除只设置 `deleted_at` 并保留 Story、漫画 Section、variant、快照和 File 引用；恢复使用 `expected_revision` 乐观锁重新进入 active 列表。

单项永久删除与清空回收站共享同一删除规则。服务端先检查 queued/running/waiting 的 Story task、Production task、Workflow 和 Chat thread 是否通过 Chapter UUID、Section UUID 或冻结输入引用目标；被占用的 Chapter 保留。批量清空在一个项目事务中删除安全项并跳过阻塞项，允许部分成功；重复清空空回收站幂等返回零计数。

永久删除会解除 current Story 指针并按外键规则清理 Chapter 自有内容。它不主动删除 `files` 或 `file_objects`，因此被其他业务资源共享或被历史引用的 Asset Store 内容继续保留。

## data_model

生命周期由 `chapters.deleted_at` 和 `revision` 表达。阻塞检查只读取项目内 `task_runs`、`production_task_runs`、`workflows`、`chat_threads` 及该 Chapter 的 `chapter_comic_states` / `comic_sections`；外部结果只包含 Chapter UUIDv7、chapter code 和稳定 error code。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/projects/:project_uuid/chapters?state=active|trashed` | GET | 按生命周期返回 Chapter 列表。 |
| `/api/v1/projects/:project_uuid/chapters/:chapter_uuid?expected_revision=:revision` | DELETE | 把 active Chapter 移入回收站。 |
| `/api/v1/projects/:project_uuid/chapters/:chapter_uuid/restorations` | POST | 以 `expected_revision` 恢复 Chapter。 |
| `/api/v1/projects/:project_uuid/chapters/:chapter_uuid/permanent?expected_revision=:revision` | DELETE | 永久删除单项；活动引用存在时返回 `chapter_delete_blocked`。 |
| `/api/v1/projects/:project_uuid/chapters/trash` | DELETE | 清空当前项目 Chapter 回收站，返回 `{deleted_count,blocked_items}`；静态路由优先于 `:chapter_uuid`。 |

`blocked_items` 每项为 `{uuid,chapter_code,error_code}`，不返回内部 ID、原始数据库错误或路径。所有响应遵守统一 JSON 信封和 `snake_case`。

## ui

| 页面 / 入口 | 说明 |
|---|---|
| Chapter 回收站 | 标题区显示待删除数量和“清空回收站”；空列表时禁用。 |
| 清空确认 Dialog | 使用 `LumiDialog` 展示不可恢复警告与数量；提交期间禁止关闭和重复提交。 |
| 部分成功结果 | 刷新 Chapter、回收站与项目摘要；显示已删除数、被阻止 Chapter code、本地化原因和安全错误码。 |
