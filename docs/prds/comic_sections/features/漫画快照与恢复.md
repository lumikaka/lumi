# 页面 / 画面段落 — 漫画快照与恢复

## overview

快照沿用当前项目形式的产品术语：普通绘本显示“绘本、页面、页面脚本”，条漫 `vertical_strip` 显示“章节、画面段落、分镜脚本”；历史图片统一称“页面图片版本”。底层 snapshot schema 与 API 字段继续使用 Chapter、Section、Storyboard 和 Variant 技术名。

该 Feature 将 Chapter 当前漫画状态冻结为不可变快照，并允许用户在确认后恢复。列表只显示版本、原因、来源、Section 数和时间；详情才安全投影按装订顺序的 `page_role`、脚本、当前图片和 Premise 参考，同时显式标注 `ready`、`missing` 或其他媒体不可用状态。

恢复不是把旧 JSON 直接暴露或修改历史 Variant，而是由服务端校验快照 schema、Chapter 当前状态和活动任务后恢复可编辑当前状态。恢复会依 `page_role` 重新归一封面、正文与封底的顺序，并校验 Section UUID 不重复、特殊角色各最多一个。普通绘本还必须至少恢复一个 `body`，因此旧版或异常的 empty、cover-only、back-cover-only 快照都会被拒绝；`vertical_strip` 仍可恢复 empty。存在活动生成时返回稳定冲突，避免生成结果写入被恢复的旧状态。

## data_model

`comic_chapter_snapshots` 保存 Chapter comic state 与 actor 内部关联、`version_no`、`reason`、`snapshot_json`、`snapshot_hash` 和时间。API `source` 由 `reason` 归类投影，schema version 来自 `snapshot_json.version`。schema v3 的 `sections[]` 冻结 `section_no`、`page_role`、脚本与当前图片版本；v1/v2 快照缺少 `page_role` 时按 `body` 读取与恢复。公开摘要只包含 UUIDv7、版本、原因、来源、Section 数和创建时间；详情中的每个 Section 返回 `page_role`，媒体只包含可解析的公开资产投影。

## api

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/projects/:project_uuid/chapters/:chapter_uuid/comic-snapshots` | GET | 返回 `{items}` 快照摘要列表。 |
| `/api/v1/projects/:project_uuid/chapters/:chapter_uuid/comic-snapshots/:snapshot_uuid` | GET | 返回单个可预览快照详情，包含每个 Section 的 `page_role`。 |
| `/api/v1/projects/:project_uuid/chapters/:chapter_uuid/comic-snapshots/:snapshot_uuid/restorations` | POST | 校验并恢复快照的角色、顺序与 Variant 指针；普通绘本要求至少一个正文页，活动生成时返回 `production_snapshot_restore_blocked`。 |

## ui

| 页面 / 入口 | 说明 |
|---|---|
| Chapter 快照 Dialog | 宽屏为版本列表与详情，窄屏纵向排列；详情按“封面 / 正文第 N 页 / 封底”标注角色，详情失败时禁用恢复。 |
| 恢复确认 | 显示版本和 Section 数，提交期间禁止关闭与重复提交。 |

## others

兼容旧快照时服务端可按 schema version 回退读取，但不向客户端暴露内部 JSON/hash。恢复成功发布 `comic:snapshot_restored`，前端重新读取漫画、任务和导出就绪度。
