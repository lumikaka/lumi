重复 1/2/3 的成功数：Lumi 为 4/6、3/6、3/6；pi 为 6/6、3/5（另 1 次超时）、4/6。三次足以验证重复机制并观察波动，不足以证明统计显著性。原始结构化报告还保留逐场景均值、范围、总体标准差及指标有效样本数。

本轮最明显的现象是添加模型场景的差距。不过 pi 可以检索安装后的源码、完整文档和内置目录，Lumi 是有限的虚拟文件系统与文档子集；系统提示词、工具、流式传输及请求预算也不同。**这是同模型下两套现有系统的任务表现对照，不是只替换 Agent 核心的控制实验。** 后续若研究差距归因，应另外建立共享资料、工具协议、提示词与预算的实验，不能修改本批证据追求同分。

## 失败证据与后续建议

1. **Lumi 猜测配置字段，完成说明缺少加载后验证。** [有文档添加模型 run-001](40195053745/lumi/tasks/pi-add-model-with-docs/run-001/result.json) 写入 `maxOutput`，实际要求 `maxTokens`；价格还缺 `cacheRead/cacheWrite`，观察到的最大输出为 0。run-002 同样失败。建议后续用可读 schema 和加载结果闭环验证配置；先补齐实验可获取资料再判断核心是否需要调整。
2. **Lumi 在资料不足时反复探索并耗尽预算。** [无文档添加模型 run-002](40195053745/lumi/tasks/pi-add-model-without-docs/run-002/result.json) 达到 16 次请求；模型仍未在 reload 后出现。建议评估无进展识别和不确定性表达，本轮未修改生产 Agent 策略。
3. **两边都存在用户目录与项目目录混淆。** Lumi [用户模板无文档 run-002](40195053745/lumi/tasks/pi-prompt-template-user-without-docs/run-002/result.json) 写入 `~/.pi/prompts`，正确用户路径是 `~/.pi/agent/prompts`。pi [项目模板有文档 run-002](40195053745/pi/2026-10-25T12-53-34.184Z_e785be65-f0a1-4811-bae3-9f4711bf62f9/tasks/06e87d698a5a86ff623a54511074bab0a5546e9f84556658fadda871a3dfd3cb/vitest.json) 把项目路径写成 `.pi/agent/prompts`。建议验证资源发现与作用域，而不只检查文件是否写入成功。
4. **pi 无文档添加模型 run-002 超过原生 300 秒预算。** [控制台](40195053745/pi-console.txt) 明确记录 `Test timed out in 300000ms`；[Vitest](40195053745/pi/2026-10-25T12-53-34.184Z_e785be65-f0a1-4811-bae3-9f4711bf62f9/tasks/cf606096ecdabe8b8026a578c34c08dc522a02bd70e94650866acaccad36ca52/vitest.json) 记录 300,007 ms；[session](40195053745/pi/2026-10-25T12-53-34.184Z_e785be65-f0a1-4811-bae3-9f4711bf62f9/without_docs/sessions/cf606096ecdabe8b8026a578c34c08dc522a02bd70e94650866acaccad36ca52/session.jsonl) 保留持续检索与推理、58 个工具调用事件及最后的 `aborted`。末尾 write 参数被截断，未见成功写入结果。证据支持“任务未在预算内完成”，未见鉴权或连接错误；无法仅凭记录分离模型推理、服务延迟和策略的贡献。保持上游 `errored`、分数 N/A，不改判为 Agent 零分或环境故障。
