# 按章、按场串行制作

本参考用于制作、续做或扩章；仅导出、改字时不额外建聊。用户指定的章节／页码、正文图数量、设定图范围、审阅节点和宿主权限始终有效。通过是实际看图后的自检结论，不能替代用户要求的审阅。到用户审阅节点时暂停后续制作，仍可保存已经完成的结果。

## 1. 项目事实与交接记录

先 `project_overview → project_setup get → book_outline`，读完相关游标。所有业务事实只经 Lumi CLI／MCP 读取；UUID、采用版本、revision、review_status 以 Lumi 当前值为准，不能以聊天承诺或本地清单判定已完成。

协调信息放在本项目可编辑的 `user-data/lumi-production/`，不写 `.lumi`、`assets`、数据库、AGENTS.md 或 CLAUDE.md。只保存本任务需要的记录，保留已有条目，禁止覆盖别章进度：

| 文件 | 唯一写入者 | 必需内容 |
| --- | --- | --- |
| `index.json` | 总聊天（单章时当前聊天） | project_uuid、原始用户范围／审阅约定、章 UUID 顺序、每章宿主聊天身份／目录、待开始章、交接文件路径 |
| `<chapter_uuid>/chapter.json` | 章节主聊天 | 原文来源、按页 UUID 排序的连续场次、每场页码／UUID、设定与场景子任务身份、当前阻塞、最终章节摘要 |
| `<chapter_uuid>/storyboard/manifest.json`、`page-<序号>.json` | 本章分镜 subagent | 原文身份／摘要指纹、用户要求、任务状态、逐页草稿路径、页数、待裁决问题；各页保存下节字段 |
| `<chapter_uuid>/storyboard-commit.json` | 章节主聊天 | 已核对页、草稿指纹、page_uuid、写入回执及 revision、待提交页与冲突；不由分镜代理修改 |
| `<chapter_uuid>/settings.json` | 本章设定 subagent | 每项 setting_uuid、variant_uuid／version_no、revision、style_digest、真实看图的 reference_basis／comparison／verdict、变化与适用页 UUID、影响范围和未解决项 |
| `<chapter_uuid>/scene-<序号>.json` | 对应场景 subagent | 分配页 UUID、上一场连续性、本页请求检查点、采用版本与核对回执、具体问题、跨场交接 |

文件可用宿主普通文件工具读写，不含密钥、Base64、临时 Web URL。身份、分场、设定变更和下一步在相应操作后立即保存。生图请求必须**先保存原参数再发起**；共享临时文件仅用来传长文本，不替代这些持久交接。没有文件写权限时保留工具结果与原请求的会话记录，说明跨聊天恢复限制，不声称已持久保存。

设定没有单独的 `record_image_review` 动作：实际看图后先保存上述证据；用于页面时以当前 `image_target.setting_readiness` 核对身份，提交原观察的 `setting_reviews`，Lumi 随页面准备／生成与导入保存依赖证据。过期证据不能只更新版本字段继续使用。

## 2. 按章分聊天

单章任务由当前聊天负责。多章时当前聊天成为总聊天，只协调范围、章节顺序、阻塞和章节摘要；第 10、11 章必须有两个章节执行单元。后章直到前章在用户范围内通过、所需用户审阅完成、交接保存并核实后才启动。未制作的范围不宣称完成。

1. 发现当前可用的 `list_projects`、`list_threads`、`read_thread`、`create_thread`、`wait_threads` 和 `send_message_to_thread`。用户要求按章建聊和续做时，在该授权范围内创建／继续章节，不将它扩展为向其他聊天发消息的权限。
2. 先读取 index，按 project_uuid + chapter_uuid 查已登记的 thread，再用 `list_threads`／必要时 `read_thread` 核对同一项目路径与章节范围。创建调用回执丢失时先查历史，找到已有章聊天就登记复用；不能只看标题重建或误复用同名书。
3. `list_projects` 找到 **project_overview 对应的准确目录**，传返回的 projectId 给 `create_thread(target={type:"project", projectId, environment:{type:"local"}})`。不选源码仓库代替作品目录，不建 worktree，不手填其他项目 ID。项目未列出时说明需要将该作品目录添加到 App；本机 CLI 经 `codex app --help` 确认支持后，可给用户 `codex app "真实作品绝对路径"` 在桌面 App 打开该目录。信任提示由用户处理，不替用户设置信任。之后重新 `list_projects` 核实，保留进度，不在错误目录创建。
4. 每次只创建／唤起当前章。创建是异步启动，不预先创建会自动执行的后章。立即保存 threadId、hostId、project_uuid、chapter_uuid 和目录；若只有 clientThreadId，待其获得真实 threadId 后再等待或发送消息，不能把它当 threadId。
5. 新章 prompt 只含下节的精简输入、技能路径、项目目录和前章交接，不复制总聊天历史。用 `wait_threads` 按返回 cursor 有界等待当前章；needs_attention／等待用户时不启动后章。总聊天用 Lumi 摘要核实章页状态和最终设定身份，再把章节摘要、最终版本及连续性交给下一章。章节聊天以最终回复交付，不要求它反向给总聊天发消息。
6. 从单章扩成多章时，原聊天已经完成／正在负责的那章继续作为该章聊天，登记其身份；总进度由当前聊天兼管。查找并复用其余章已有 thread，仅为尚无聊天的章创建新 thread。恢复多章时同样先校准 Lumi，再继续原章节 thread，不能把 passed 页重新分配为首生成。

总聊天只读 index、章节摘要、阻塞、必要前章交接，以及 `book_outline`／`pages list(summary_only=true)` 的状态摘要；不调用 `chapters get`、不读原文文件、逐页草稿或整章分镜，也不调用含本章原文的 `render_prompt`。长原文已经在总聊天的用户消息中时，不能声称从未进入上下文；后续只按来源路径／章节 UUID 交接，不再回显。原文尚未入库时，由章节主聊天从用户给出的来源读取并经 Lumi 保存。

章内创建分镜／设定／场景 subagent 用 `spawn_agent(fork_turns="none")`，后续给相同代理用 `followup_task`／`send_message`。代理身份失效时，确认旧代理已停止写入，再用保存记录重建同一职责；不能同时留下两个分镜代理、两个设定代理或两个代理写同一场。

## 小说分镜委派

仅适用于小说原文改编；章节主聊天先查本章交接与 `pages list(summary_only=true)`，必要时按页 `pages get` 校准分镜是否覆盖用户范围、正文／画面完整且符合最新要求。缺图、pending 或 needs_revision 是图片状态，不能据此认定缺少分镜。已有可用分镜且用户只要配图时，启动分镜 subagent 的数量为 **0**，直接进入划场与原有设定／场景流程；小范围改字仍按原规则处理。

缺分镜或用户明确要求重做时，每章为本次分镜任务启动**一个独立分镜 subagent**，使用 `spawn_agent(fork_turns="none")`。不能由总聊天代替章节主聊天启动，不能按页拆成多个分镜代理，也不能再派通用分页代理重复工作。分镜是设定制作和场景制作之前的草稿阶段。

1. **登记与精简输入**：章节主聊天在 `chapter.json` 保存 `storyboard_task`（任务状态、原文来源与指纹、用户要求指纹、agent 身份、草稿目录、提交进度路径）。先查已有身份和草稿，任务创建回执不明时先核实代理列表及记录，避免重复启动。通过 Lumi 取得本章原文及实际模板，`render_prompt` 限定 `context_chapter_uuids=[]`、`context_setting_uuids=[]`；把本章所需的完整 prompt／write_back、格式与节奏约束保存为任务输入文件，不夹带整书原文、其他章节正文或父聊天历史。只交本章原文的准确来源／获取参数、用户要求、任务格式、草稿绝对目录及必要的前章连续性交接。subagent 只读取这些输入；通过 CLI／MCP 读原文时限于本章，不访问 Lumi 内部目录。
2. **持久逐页草稿**：分镜代理每完成一页立即写 `storyboard/page-<序号>.json`，再更新 manifest 的已完成页与待办。每页必须有 `page_number`、`source_spans`（本章段落／行或字符范围与短引文，可逐字回查）、`title`、`page_role`、`description_md`（逐字旁白／对白）、`utterances`（依阅读顺序的 `kind`、`speaker`、`text`；旁白显式标记、未知说话人列为问题）、`storyboard_md`（构图、画面动作、表情、逐字绘入文字与气泡指向）、`continuity`（入／出时空、人物身份及服装、道具持有／位置／状态、未完动作）。按实际逐页镜头计划组织，不补造原文事件。manifest 保存输入指纹、页序、页数、状态和待裁决问题，不能用一份仅在内存中的整章 JSON 替代逐页保存。
3. **只交路径**：分镜代理只写草稿，不调用 Lumi 写工具、不生图、不创建其他 subagent；最终仅回草稿绝对路径、页数和待裁决问题。章节主聊天逐页读取对应草稿与原文定位，核对覆盖、事件因果、旁白／对白逐字内容、说话人、动作和跨页连续性；有疑问用原分镜代理修订，不能把整章草稿复制进回复或交给总聊天。需要用户裁决的问题先保存，能合理判断的由章节主聊天处理。
4. **串行写回，再划场**：章节主聊天按 [动作参数与版本](mcp-usage.md#动作参数与版本) 映射字段；创建每页前重取 `pages list` 的父集合 revision，更新已有页用该页最新 revision。每页核对与提交后立即保存 `storyboard-commit.json` 的草稿指纹、page_uuid、实际回执／revision。部分缺页仅补缺页，重做沿用现有页 UUID；页数变化先核对范围及页序，不擅自删除已有图片或用户编辑。revision 冲突时重读该页并合并，不只换 revision 覆盖。分镜写回、页序与连续性核实完成后才按下一节划场，继续**每章一个设定 subagent、每场一个场景 subagent、逐页实际看图审阅**。
5. **中断恢复**：先读 `storyboard_task`、manifest、逐页文件和提交进度，再从 Lumi 核实已提交页；回执丢失时按页 UUID／原文定位与实际正文分镜比对，确认已保存就补记进度，不重复创建。输入未变且草稿完整时直接继续核对／提交，未完成时唤回原分镜代理只补剩余页；不重启整章。输入或用户要求改变时先判断影响页，保留未受影响草稿与已保存进度，修订仍交原代理；原代理不可恢复时确认停止后再交接替代者，并如实记录额外启动。草稿与进度是协调记录，Lumi 当前内容及 revision 才是已写回事实。

总聊天最终仅收章节摘要、阻塞和必要交接（页数、状态、最终设定身份、跨章连续性）；章节原文及整章草稿保留在章节及分镜职责范围。验证上下文和 token 时分别统计总聊天单次输入峰值，以及总聊天、所有章节聊天与所有 subagent 的累计输入、缓存输入、未缓存输入和输出，使用真实宿主用量；上下文减少不等于总 token 减少。

## 3. 章节先划场，再统一设定

章节主聊天读取已保存的章节原文、所有目标页分镜和逐字旁白／对白，结合前章交接按剧情及画面连续性划分**连续页段**。通常以地点、时间、行动目标或视觉连续性变化为分界，不按固定页数机械拆分，不把一页分给两个场景代理。保留原页序与 UUID；未保存分镜时先完成文本草稿、审阅并写回，再分场。

汇总全章人物、身份与服装阶段、关键道具的持有／位置／状态、场景时空、适用页 UUID。衣着可放在对应 character 设定或独立 reference 中，按已存在的数据模型保存，不发明 clothing 类型。章节主聊天把汇总、用户要求、原文来源、分场表和前章最终设定交给**唯一设定 subagent**。

设定 subagent 用 `settings list/get` 核对已有设定与当前采用图片，先复用；只补建或修改需要的项。保留同一身份的 UUID；剧情中真实的服装／道具／场景阶段变化应有可区分的参考项及适用页，不能覆盖旧阶段让前页被错误追溯。实际看过采用图后保存核对证据，返回采用版本清单、改了什么、哪些页适用和未解决项。只看提示词或导入成功不算通过。

设定图沿用 [批量设定图](batch-settings.md) 或 `image_target → 宿主生图 → import_image`，看实际采用版本后记证据。

章节主聊天核实设定身份、核对证据和适用页段后，才启动第一场。每次启动／恢复场景仅交付：项目目录与 project_uuid、chapter_uuid、按顺序的页码／page_uuid、本场用户要求与审阅节点、原文来源及必要原文、已保存分镜的获取方式、采用设定及核对记录路径、上一场／前章的连续性、可写范围。无需整本原稿或父历史。

## 4. 一场一代理，一页一闭环

上一场全部目标页通过并由章节主聊天从 Lumi 核实后，才创建下一场独立代理。场景代理不得自行再派并行画页代理。每页先重读 `pages get` 和当前审阅状态，再按 [页面生图](page-images.md) 执行：

1. **准备参考**：读本页原文、分镜、采用设定和适用页段，检查与上一页的连续性；核实 setting_reviews 仍绑定当前图／revision／画风。参考缺失或设定有误交回设定代理。
2. **生图并导入**：保存本页准备结果，`prepare_page_image → 看返回的同一路径合图 → 宿主 imagegen → 立即 import_image`。原样保留 generation_prompt 与 preparation，保存实际输出路径及导入回执；不为下一页提前生图。
3. **看实际采用图**：通过 `pages get` 确认当前 variant_uuid 和实际处理版，`read_image` 实际查看；被 crop／pad 后尤其要看处理版。子任务只看过宿主原图不能代替此步。若生成返回 is_current_image=false，先读当前采用版本，不能审阅旧结果冒充当前图。
4. **逐页核对并保存**：逐字核对旁白、对白、姓名、标点及说话人／气泡指向，核对人物肢体、身份、服装、道具状态和位置、画风与前后页连续性。读不清的字不记 passed。用 `pages record_image_review` 绑定当前 variant_uuid 与 revision 保存具体观察；修订同一记录带 expected_review_revision。本页通过且未到用户暂停节点，再推进下一页。

若子任务缺少宿主生图、读图或导入能力，先报告实际缺失工具及本页请求给章节主聊天。主聊天在相同权限与范围内**代执行这一页所缺步骤**，将真实返回值／路径交回原场景代理；能看实际图的执行者负责记录自己的观察，未看图者不得代写 passed。不能让整场移到另一代理并行重跑，也不能因委派静默切换服务。宿主也无该能力时保存阻塞与待审状态，等待所需能力／用户输入。

场景代理仅向章节主聊天回报页码／UUID、采用 variant_uuid／version_no、review_status、必要的具体问题和跨场细节（时空、服装、道具归属、动作衔接）。完整生图提示词、图片和原文保留在工具及任务记录，不灌回总聊天。章节主聊天用 `pages list(summary_only=true)`／`book_outline(chapter_uuid)` 读完游标核实，并按需 `pages get`；不能只信代理说“通过”。

## 5. 页面纠错与设定返修

页面画错但设定正确：当前场景代理记录 needs_revision 和具体问题，只修本页，实际看修正版并重新记录，通过后继续。

设定有误：当前场景立即停止生图，保存问题、受影响的设定／页 UUID 和连续性；章节主聊天唤回**本章原设定 subagent**，其他场景不得开始。设定代理修正并实际看图，返回新旧版本、变化、按剧情划定的适用页段与影响页。区分“原设定画错”与“剧情中后来换装”，不能一律重画之前所有页。

章节主聊天把受影响已完成页列成复核队列，逐个交回其所属场景代理串行处理，必要时跨场、跨已完成章通知总聊天；仍在用户授权范围内才修改。超出范围的页记录明确待办并说明对交付的影响。**设定改变不会保证旧页 review_status 自动失效**，即使 Lumi 仍显示 passed 也要实际复核。符合新适用设定的页可保留图并更新观察；不符的保存 needs_revision、只修具体问题再核对。不能仅换核对记录中的版本号，也不能把正常的后期设定套到早期页。

复核队列清空、设定证据通过后，将最终设定与连续性送回**原场景代理**，从当前页恢复；不重启全场或整章。旧代理无法恢复时先确认其不再写入，再交接保存记录给替代代理。跨章最终交接必须使用返修后实际采用的设定版本。

## 6. 中断、未回报与完成

恢复先读持久交接和 Lumi 当前事实，再联系已登记的章节／场景；子任务可能已导入但尚未回报，**先查 Lumi 再决定是否生成**。原场景仍运行时先协调其状态，不派第二个写同一页。

| Lumi 当前状态 | 恢复动作 |
| --- | --- |
| passed | 跳过；有待办设定影响复核时先执行该复核 |
| pending／已有图无有效核对 | 先看当前实际采用图并记录结论，不生新图 |
| needs_revision | 读完整观察，只修具体问题；若根源在设定，走返修流程 |
| missing_image | 确认无未决请求后才首次生成 |

导入响应丢失：读 `pages get(include_versions=true)`／当前摘要核对已保存版本与请求回执，已挂载就先审；不重复 import_image。只有未导入且准备仍有效、真实输出路径可用时继续原导入。路径失效或 preparation 已过期则重新准备和生成，不能扫描宿主输出目录或改签名强行导入。
