# Guide：生成、导入与选择漫画图片

用于生成、导入或选择页面图片版本。

## API 调用顺序和说明

1. 先用 `read_agent_doc` 阅读 `/api/v1/agent-docs/api/comic-section.md` 和 `/api/v1/agent-docs/api/comic.md`；生成时再读 `/api/v1/agent-docs/api/generation.md` 和 `/api/v1/agent-docs/api/task.md`。
2. 生成两个及以上 Section 时，用 `request_api` 只允许调用一次 Section 列表接口，同时读取 `page_role`，把用户的“封面 / 第 N 个正文页 / 封底”映射为保持装订顺序的 Section UUIDv7；不要把 `section_no` 直接当作正文页码，也不要逐个读取目标 Section。
3. 多 Section 生成必须只调用一次 `POST /api/v1/projects/{project_uuid}/chapters/{chapter_uuid}/comic-image-generation-batches`。禁止循环调用单图接口，也禁止使用通用 `image_gen` 代替漫画图片任务。
4. 只生成一个 Section 时，可读取该 Section 后调用单图生成接口；导入图片或选择已有 variant 时读取目标 Section、页面图片版本和最新 revision。
5. 图片生成任务会冻结目标的 `page_role`。任务运行期间不要修改页面角色；角色漂移会使服务端拒绝提交生成结果，此时先重读 Section，再按当前角色重新生成。
6. 生成任务按需读取 Production Task 状态和事件；完成或选择后重读 Section 和页面图片版本。

批量接口由服务端使用每个 Section 的当前 Storyboard、项目画风、自动选择的设定引用和项目图片模型；不要发送逐页 Prompt、引用或模型参数。没有 Storyboard 时不要盲目生成。本地文件未成为 ready upload 时引导用户使用界面导入。

接口返回 `queued` 只表示图片任务已创建，不能报告为图片已经生成完成。API 细节以所读 Contract 为准。
