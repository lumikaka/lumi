# Guide：初始化新项目并开始自动生成

## API 调用顺序和说明

1. 先用 `read_agent_doc` 读取 `/api/v1/agent-docs/api/project-setup.md`，再用 `request_api` GET 当前 Project Setup；需要启动时还必须读取 `/api/v1/agent-docs/api/workflow.md`。
2. 把首页第一句话完整保留为 `original_input`，不要改写、截断或用于文件夹命名。从中分别整理 Project Setup 的 Setup Draft 和生成 Brief 草稿；Brief 不得成为第二份绘本结构配置。初始化阶段只维护这一份 Setup Draft，不得创建、选择或切换 Candidate。
3. 只补问会显著改变首章结果的信息，例如主角与世界、核心目标或冲突、目标年龄与基调、结局方向，或尚未确定的绘本结构字段。信息足够时不提问；信息不足时原则上一次询问 1～3 个相互关联的问题，只有回答冲突或仍无法形成合法规格时才追加一轮。不要询问镜头、Section 数、分镜数或模型参数。
4. 用 `request_api` PATCH Setup Draft 并携带最新 `expected_revision`，同时把不超过 4000 字符的生成 Brief 写入 `generation_brief`。可以合理补全的剧情细节作为明确标注的 Agent 建议展示；不得伪装成用户选择。若 `reference_plan.items` 非空，只说明已附带多少张视觉参考，它们会按顺序自动用于画面生成；不得逐项询问、展示或修改角色、标题、说明和参与状态。
5. Setup Draft 完整后，向用户一次展示：项目名称、语言、整体画风、绘本形式、比例、形式专属选项、字段来源、视觉参考数量及自动使用说明，以及由原始需求、用户补充和 Agent 建议组成的生成 Brief。参考图会实际进入视觉生成，但不会仅凭图片自动改写故事；自动生成流程会创建或复用 `vol01.ch01`、生成 1～6 个正文 Section；普通绘本另建封面，默认生成封面和第一个正文页的成品图，`vertical_strip` 则只生成第一个画面段落的成品图；Premise 仍会生成既有 Setting Image。
6. Setup 进入 `pending_confirmation` 后，运行时会免确认提交并完成 finalization，然后直接从已定稿的 `generation_brief` 创建受控自动生成 Workflow，中间不会生成危险操作确认卡，也不会再次调用模型。该免确认例外只适用于运行时可信生成的新项目 finalization；其他危险操作仍使用全局确认协议。不要自行调用 finalization、`request_user_input` 或重放请求。
7. Workflow 的 title、Provider、模型和幂等键由服务端绑定。不要重新 GET、拼装 `story_prompt` 或调用 Workflow route。
8. 自动生成 Workflow 创建后，会以内联卡片显示在当前来源 Turn 内，当前 Turn 投影为 `waiting_for_workflow` 并释放 Agent worker。不要轮询、读取 Workflow 进度，也不要手工创建 Story、Chapter、Premise、Section、图片、生成或导出任务。Workflow 成功、失败或取消后，运行时会用终态 Tool Result 恢复同一 Run；读取该结果并只输出一次最终说明。

用户在 Setup 完整前明确要求继续修改时，继续维护草稿，不得提前补齐并启动。若 Workflow 创建前失败，如实报告错误并停止；若终态失败或取消，根据安全终态结果说明，不得退化为手工生产，也不得自动创建第二个 Workflow。draft 阶段不得启动自动生成流程；bootstrap 在 ready 后的 Workflow 创建也只能由运行时恢复和执行。
