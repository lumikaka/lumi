# Guide：初始化新项目并启动 YOLO

## API 调用顺序和说明

1. 先用 `read_agent_doc` 读取 `/api/v1/agent-docs/api/project-setup.md`，再用 `request_api` GET 当前 Project Setup；需要启动时还必须读取 `/api/v1/agent-docs/api/workflow.md`。
2. 把首页第一句话完整保留为 `original_input`，不要改写、截断或用于文件夹命名。从中分别整理 Project Setup 的 Setup Draft 和 YOLO Brief 草稿；Brief 不得成为第二份绘本结构配置。初始化阶段只维护这一份 Setup Draft，不得创建、选择或切换 Candidate。
3. 只补问会显著改变首章结果的信息，例如主角与世界、核心目标或冲突、目标年龄与基调、结局方向，或尚未确定的绘本结构字段。信息足够时不提问；信息不足时原则上一次询问 1～3 个相互关联的问题，只有回答冲突或仍无法形成合法规格时才追加一轮。不要询问镜头、Section 数、分镜数或模型参数。
4. 用 `request_api` PATCH Setup Draft 并携带最新 `expected_revision`。可以合理补全的剧情细节作为明确标注的 Agent 建议展示；不得伪装成用户选择。若 `reference_plan.items` 非空，逐项核对标题、`reference_role`、`include_in_yolo` 和用户写明的 `instruction`；需要调整时调用 reference PATCH，每次成功后重新使用返回的新 revision。只能说明“已收到图片及用途”，不得声称已经看过图片像素，也不得自动分类图片。
5. Setup Draft 完整后，向用户一次展示：项目名称、语言、整体画风、绘本形式、比例、形式专属选项、字段来源、逐项视觉参考计划，以及由原始需求、用户补充和 Agent 建议组成的 YOLO Brief。明确说明参考图会实际进入 Premise 视觉生成，但不会仅凭图片自动改写故事；同时说明固定产出范围：YOLO 创建或复用 `vol01.ch01`、生成 1～6 个正文 Section；普通绘本另建封面，默认生成封面和第一个正文页的成品图，`vertical_strip` 则只生成第一个画面段落的成品图；Premise 仍会生成既有 Setting Image。
6. 用 `request_api` 请求 `POST /api/v1/projects/{project_uuid}/project-setup-finalizations`。收到确认要求后，下一次必须单独调用 `request_user_input`，只问一个稳定问题：
   - `question_id` 必须精确为 `confirm_setup_and_start_yolo`。
   - 第一项是安全推荐项，例如 `继续修改 (Recommended)`，表示既不定稿也不启动。
   - 非首项是明确确认项，例如 `定稿并启动 YOLO`，说明定稿后会立即启动上述固定范围的 YOLO。
   - `confirmation` 原样绑定 finalization 返回的 route、Project、target、revision 和 fingerprint，`confirm_option` 指向确认项。不要自行重放 finalization。
7. 用户选择确认项、运行时自动完成 finalization 后，重新 GET 并确认 `setup_status=ready`。把 `original_input`、用户补充和已经展示的 Agent 建议整理为不超过 4000 字符的 `story_prompt`，调用受审的 `POST /api/v1/projects/{project_uuid}/workflows`；title、Provider 和幂等键由服务端绑定。
8. YOLO 创建提交后，Workflow 会以内联卡片显示在当前来源 Turn 内，当前 Turn 投影为 `waiting_for_workflow` 并释放 Agent worker。不要轮询、读取 Workflow 进度，也不要手工创建 Story、Chapter、Premise、Section、图片、生成或导出任务。Workflow 成功、失败或取消后，运行时会用终态 Tool Result 恢复同一 Run；读取该结果并只输出一次最终说明。

如果用户选择安全项、Other、取消，或者明确只想继续修改，不得启动 YOLO。若 YOLO 创建前失败，如实报告错误并停止；若终态失败或取消，根据安全终态结果说明，不得退化为手工生产，也不得自动创建第二个 Workflow。draft 阶段不得启动 YOLO；bootstrap 首个 Turn 在 ready 后也只能读取事实、恢复 finalization 或调用上述 YOLO route。
